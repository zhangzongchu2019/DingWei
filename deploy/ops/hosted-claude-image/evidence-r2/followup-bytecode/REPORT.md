## Cause and narrow scope expansion

The real shared H3 source_kit loads tools/sessionhelper/package_release.py from the source checkout. Python ordinarily writes a __pycache__ there before build() checks for untracked source, so a repository with no ignore rules rejects itself as source_not_clean. Prior runs with PYTHONDONTWRITEBYTECODE=1 hid the defect; those local readings were not full canonical acceptance and are superseded by the plain-invocation evidence here.

The added R2.3 instruction narrowly expands the earlier Claude-directory-only scope to shared H3 prepare_context.py and its existing test_build_definition.py. Production change: import sys; save dont_write_bytecode, set True only while exec_module loads the packager, restore in finally before build/verify. No exception is swallowed, no ignore rule added, no untracked file removed, and no cleanliness gate bypassed. Only this H3 function changes; all 15 Claude source paths/subtree, package_release and other H3 functions stay unchanged.
