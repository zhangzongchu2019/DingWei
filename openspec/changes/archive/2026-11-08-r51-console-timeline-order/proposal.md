# 提案

## Why

回合进行中提交的用户消息会先进入待提交区，Hub 的接收确认可能晚于该回合的 Agent 输出到达。当前确认事件触发建卡时总把用户卡追加到时间线末尾，导致它显示在回复之后；刷新后历史按相同事件序列重放，又会稳定重现颠倒。此变更按发送时刻统一定位首次渲染、刷新回放和历史分页的节点位置，修复可见顺序而不改变投递协议、Hub 事件或时间戳来源。

## What Changes

- 增加统一时间线节点定位逻辑，使用卡片所带发送时刻在已有节点中插入。
- 用户输入、回合输出及提及回复走同一定位规则；历史分页使用该规则保留历史与实时节点的顺序。
- 增加真实浏览器历史回放回归、旧实现对照和追加变异。

业主派单与 rulings ㊶：[业主裁定 e4238e26](https://git.code.tencent.com/wego-ai/dingwei/blob/e4238e263439cd694a8597bac8db57e63634d46f/docs/rulings/S-TEAM-MIGRATE-HOSTED-20261017.md)。

## 范围与影响

仅改 `view-service/renderer-canary-sse.html`、浏览器回归和其 suite 登记，以及本变更规格与证据；不改 Hub、helper 协议、迁移或版本位，不增加依赖。

## 待确认假设

- 当已有时间线节点与新节点缺失发送时刻时，保留已有相对顺序并将无时刻节点追加；当前派单指定的迟到接收场景均带发送时刻。
