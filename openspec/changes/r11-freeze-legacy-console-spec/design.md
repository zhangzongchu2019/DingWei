# Design

## Context

见 proposal 的 Why 与代码基线 context。当前 UI、Console/Agent/shared 路由、PM 草稿与异步回调都有旧规格写路径，存储还保有门和审计记录。只移除导航不能满足冻结，直接删除旧表会破坏历史及在途任务。

## Goals / Non-Goals

- 目标：把冻结约束放在全部旧规格写路径共有的服务端提交边界，原旧列表仅业主只读可查，不新建独立历史入口；覆盖 LCS-001～005。
- 边界：本轮只有文档；实际切换控制、发布、回滚须另获授权。既有任务执行继续，R10 的新任务管理及新 PM 问答不在 R11 实施范围。

## Decisions

1. **完整入口清单而非按钮清单（LCS-001、003）。** 实施前从 `cmd/workpulse/console_routes.go` 逐条映射读/写、回调和存储效果。至少包括 `/api/console/specs` 及单项修订/派生/归档、shared 编辑/versions、Agent 直写/inferences、PM 草稿冻结/结果/定稿、agent-review/criteria、presplit 会改规格的操作、旧模板确认及后台重试。各模块中的旧规格写入必须同样拒绝；无关任务进度不可按 URL 前缀粗暴关闭。相比只在页面禁用，此方案能覆盖旧客户端和迟到回调。
2. **不把旧状态迁成新状态（LCS-003、004）。** 历史门、模板确认与 final 记录保留原值；停用的是可执行门，不是将所有门填成通过。拒绝日志如需新增，另走操作审计，不改写历史业务结论。相比批量 archive/清理表，此方案保留可比对的证据。
3. **查询复用数据而不复制（LCS-002、004）。** 复用原旧列表/详情，仅可信业主身份可见且只读；非业主入口隐藏并在读取边界拒绝返回内容/摘要。老深链接按同样业主只读边界处理。不另建历史查询/检索入口，不新增共享链接治理工程或读取授权。冻结后保留一个月，清理另行请示，本变更不包含自动清理。
4. **统一生效点与并发约束（LCS-005）。** 采用可由服务端在事务提交边界判断的切换控制；具体配置/持久化机制待核后补设计，禁止在进程间各自凭本地时间判断。冻结和写事务竞争测试必须证明无冻结后追加。既有任务进度与旧规格对象写入分别列出效果，逐项回归；若现有写路径耦合，先解耦再切换，不能以例外继续写规格。

## Risks / Trade-offs

- 迟到异步回调/DB 触发器仍写旧对象 → 按路由、handler、存储方法、后台生产者四向清点，并在 SQLite/PostgreSQL 验证。
- 老共享链接与隐私策略冲突 → 已按 R11-PM01/03 批复限定业主只读列表；现有读取路由仍须核验此边界，不新增共享链接工程。
- 在途任务与旧门状态耦合 → 用固定在途清单和数据快照验证 LCS-005；不宣称冻结已解决整个任务平台迁移。

## Migration Plan

PM01～03 已批；按简化补旧列表业主只读边界设计，再实现、回归、独立审阅和预发；平台架构组公告统一生效点后按 GO 执行。旧列表业主只读与拒写约束必须作为一致发布集，不新建查询入口。

切换后若出现追溯缺口，暂停受影响的新合并/浏览入口并修复，保留历史只读；不得通过回滚页面重新开放旧格式新需求。具体发布/回滚命令由获权实施任务提供，本规格不授予执行权。

## Open Questions

PM01～03 已按业主答复写回；核心实现事实见下文。剩余 T-05/T-07/T-08 仍需按新范围实现、验证及另获预发 GO，不能以 PM 已批或 strict 通过冒称完成。

## 本轮核心实现决策（LCS-001/003/004/005）

- 开关 `WP_LEGACY_SPEC_FROZEN` 未配置/false 时不主动冻结；true 在启动迁移后、接流前把 SQLite 单例状态锁存为 frozen。非法值拒绝启动。已冻结数据库不会因下次漏配或 false 自动解冻，无公共解冻接口；切换 GO 仍由架构组执行。HTTP 统一拒绝为 409 / legacy_spec_frozen，说明改用仓库 OpenSpec。
- 旧规格表和草稿/门/生成请求/模板表的 INSERT/UPDATE/DELETE 由新迁移中的触发器在同一数据库写事务内校验冻结位。正文、历史审计及已有门不被批量改写；任务、任务证据、问答/阻塞数据不是冻结表。SQLite 是实际旧规格存储，PG 承载新平台身份，不能虚构第二份 PG Spec 表。
- 服务端变更 handler、迟到 WS 结果、后台生成重试和实际生成信封派发持有同数据库锁文件的共享租约；启动冻结先取排他租约再提交冻结位。锁文件与数据库放同目录；独立打开的同库进程共享同一锁 inode，禁止运行中删锁文件。锁采用上下文可取消等待，派发租约覆盖实际送出，已排队生成信封在真正交给 helper 前也重核。数据库提交边界继续覆盖未持租约的直接 store 调用。
- 在途任务进度、执行证据、问答/阻塞日志和普通消息不持旧规格写租约，也不被规格表触发器阻断；新拆分/生成、模板签核与迟到规格结果不能借这些路径改写旧规格。
- 已交核心阶段未改 LCS-002 的导航与读取权限；本次文档按批复缩减后，T-05 仍须实现原列表仅业主只读边界，不把原 GET 权限保留当作最终验收行为。查询页面的历史标注随 LCS-002 后续一并交付，核心阶段不冒称整个 R11 已完成。

## 核心入口与数据效果清单

| 写入/派发类别 | 守卫落点 | 冻结后效果 |
| --- | --- | --- |
| Console 新建/PATCH、shared PATCH/versions、Agent direct/inferences、版本/派生/归档/编辑控制 | `console_specs.go`、`console_spec_inference_assist.go` 的 handler 共享租约；数据库 trigger | HTTP409 明确拒绝，无新修订/历史改写 |
| workflow、agent-review/criteria/confirm、presplit/候选确认、旧 PM 草稿/派助/结果 | 对应 handler 共享租约；旧规格/flow/request/模板表 trigger | 不执行旧生成门，不伪造定稿或通过 |
| 旧模板 source/draft/角色回执和模板绑定生成 | `pilot_template.go`；pilot_spec_source 与 pilot_template 表 trigger | 不追加旧模板或借确认创建旧规格 |
| WS review/criteria/PM/presplit 迟到结果；后台 spec-agent reconciliation | callback/reconciler 共享租约；事务 trigger | 消费旧结果但不修改历史，不再发旧生成请求 |
| 生成信封直接派发、切换前 durable queue 的延迟送出 | RouteEnvelope 与 drainSessionDeliveries 的实际发送租约 | 冻结后拒发；旧排队信封终止为 dead，原请求业务记录不变 |
| 直接 store/SQL 写入旧对象 | 26 表 INSERT/UPDATE/DELETE trigger | 与冻结位事务串行，完整提交或拒绝 |
| 既有任务进度/用例结果/独立确认、问答阻塞日志、普通消息 | 不套旧规格守卫；保持原鉴权 | 原获权调用继续，不能借此修改旧规格表 |

全通道测试定位 `internal/m8/legacy_spec_freeze_test.go`；表清单/原子性/历史/在途测试定位 `internal/store/legacy_spec_freeze_test.go`。旧规格业务表在 SQLite；PG 身份仍走原鉴权链，不能宣称存在两份 Spec 业务库。

此阶段只在现有页面增加历史提示，未实现新批复的业主读取限制；LCS-002/T-05 及预发 T-08 仍不完成。
