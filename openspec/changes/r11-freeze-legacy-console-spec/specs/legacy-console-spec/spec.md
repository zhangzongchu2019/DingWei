# 旧 Console Spec 冻结增量

## MODIFIED Requirements

### Requirement: LCS-001 旧规格写入控制
切换生效后系统 MUST 在服务端拒绝所有旧规格的新建、修订、派生以及修改正文、验收项、草稿、归档标记或门状态的操作；权限角色、旧编辑 capability、Agent 凭据和异步回调均不能绕过。拒绝结果 MUST 以 HTTP 409 和 legacy_spec_frozen 明确表示旧规格已冻结、引导使用仓库 OpenSpec，且不能报告写入成功或产生修订/出站生成请求。

#### Scenario: LCS-S001 合法编辑者追加修订
- **WHEN** 原合法编辑者在切换生效后提交旧规格修订
- **THEN** 服务端返回冻结拒绝且正文、修订号和历史事件不因该业务写入改变

#### Scenario: LCS-S002 无 Agent 身份直接写入
- **WHEN** 未携带有效 Agent 专属凭据的调用者请求 Agent 直写入口
- **THEN** 请求仍被拒绝，冻结不放松身份校验

#### Scenario: LCS-S005 旧通道和迟到回调无法绕过
- **WHEN** 调用者通过 shared PATCH/versions、Agent/helper、PM 草稿或切换前已派出的生成结果回调尝试修改旧规格
- **THEN** 每个通道均拒绝写入，不生成新规格、修订、签核或门状态

### Requirement: LCS-002 旧规格读取与入口
切换后 Console MUST 从普通导航、默认工作区及新需求入口移除旧 Spec 的列表/编辑入口，并提供明确标注“历史只读”的独立查询入口。历史查询 MUST 按原授权边界返回编号、标题、正文与修订，可分页检索且包含可获权的已归档记录；不能扩大已有共享或 principal 可见范围。历史深链接不能进入可编辑界面。

#### Scenario: LCS-S003 列表过滤
- **WHEN** 已登录用户从普通工作区浏览新需求并另行打开历史查询
- **THEN** 普通入口不展示旧 Spec 工作区；历史入口仅返回该主体可查询记录，并能显式包含其已归档记录

#### Scenario: LCS-S006 越权或历史深链接
- **WHEN** 用户以他人旧规格编号查询或打开已有深链接
- **THEN** 越权查询不返回他人的内容或摘要，获权深链接仅呈现带历史标记的只读详情

### Requirement: LCS-003 旧格式生成与审结门
切换后系统 MUST 停用旧格式生成门、逐条签核及其发起/确认写操作；不得以“禁用门”为理由自动把旧规格定稿或宣告业务完成。历史审阅、验收和状态记录只读保留，新 OpenSpec 流程不读取旧门作为准入条件。

#### Scenario: LCS-S004 未满足审结条件
- **WHEN** 用户或旧客户端尝试提交生成、逐条签核或定稿
- **THEN** 系统拒绝动作，不自动改变旧状态，也不以旧门缺项阻塞新 OpenSpec 浏览

#### Scenario: LCS-S007 无后台继续生成
- **WHEN** 切换生效后旧定时重试、队列或自动生成处理再次执行
- **THEN** 不向 Agent 发出新的旧规格生成/签核任务，历史请求的拒绝不会伪造成已通过

## ADDED Requirements

### Requirement: LCS-004 历史保留与事实边界
系统 MUST 保留所有已有旧规格（含 V2.3）的正文、修订、来源和审计记录，不批量转换为 OpenSpec 当前规格，不因冻结删除或重写历史。查询 MUST 明示历史材料不代表当前仓库行为。

#### Scenario: LCS-S008 冻结前后历史一致
- **WHEN** 对同一旧规格的正文、修订内容与历史审计进行切换前后比对
- **THEN** 历史记录保持一致且查询页面显示历史只读提示，不生成对应 OpenSpec 规格

### Requirement: LCS-005 切换时点与在途边界
系统 MUST 使用默认关闭的 WP_LEGACY_SPEC_FROZEN 配置，由平台架构组批准开启后持久化统一生效点，约束旧规格写入，使与切换并发的写入要么在冻结前完整提交、要么在冻结后完整拒绝，不能部分写入。已在实现中的任务按原方式继续；冻结不得顺带阻断消息、任务进度或执行证据记录，但这些路径不能再修改旧规格原文或门状态。

#### Scenario: LCS-S009 跨越生效点的写入
- **WHEN** 一个旧规格写请求与切换同时发生
- **THEN** 最终只能观察到生效前完整提交或生效后完整拒绝，不出现正文与修订号分离或冻结后追加

#### Scenario: LCS-S010 在途任务继续
- **WHEN** 已存在的实现任务在冻结后提交任务进度或执行证据
- **THEN** 原获权任务操作仍可执行，旧规格正文、验收与门状态不被该操作改写
