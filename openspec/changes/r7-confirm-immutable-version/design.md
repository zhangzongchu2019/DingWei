# Design

## Context

旧记录只有数据库 Spec 修订与正文摘要，基线/context 列明已核代码。本变更从 d1a7a686 起，只规定未来行为；不实现 API、存储表或迁移。R7 与 R6 共同依赖逐主体仓库 ACL、commit 可读验证与 PM 冻结的比较政策，不等 R5 页面上线才定义契约，但不能绕过其安全边界。

## Goals / Non-Goals

- 建立不可变确认事实、可核查有效性与安全显示；覆盖 R7-001～007。
- 不实现 R8 状态机、R9 多渠道 PM 回应、不添加普通 MR 必点确认门、不推导验收/发布、不改 R11。

## Decisions

1. **事实与当前有效性分开（R7-001/003/005/007）。** 确认事实至少含受控 Git 实例与稳定仓库身份、规范变更目录、完整 commit、可信确认人、服务端 UTC 时刻与明确含义。ref 只能选取目标，不进入事实身份。历史原值不能被 HEAD 更新覆盖。当前有效性是相对另一个明确 commit 的判定，不能通过修改原记录「延长」确认。
2. **确认提交不跟随并发 HEAD（R7-001/004）。** 客户端提交实际展示过的 commit，服务端验证坐标、当前资格与权限，再持久记录同一 commit；若目标已变，只能留历史事实并显示差异，不确认未审看的新内容。幂等关联用于同一操作重试，不能跨 commit 消重或复用。存储事务/并发与接口细节待实施设计，不先写新 endpoint/错误码。
3. **共享比较契约（R7-003/004/005，R6-006/007）。** 输入为同仓同变更的旧/当前 SHA 与带版本的已批准策略，输出为实质修改、已证无实质修改或无法判定，并留文件差异与依据。明确需求、场景、范围或任务语义变化必须判实质；无关提交不得误失效。R7-PM01 已批 A 及三类豁免，具体已实现范围见下文追加决策；默认不开启自动比较。未知不是通过：界面显示待核对，旧确认不能覆盖新内容。PM 策略变化后须重新判定，保留旧判定依据，不改原确认事实。
4. **强推防护不依赖祖先关系（R7-005）。** 两端对象仍可读时比较固定 SHA 内容，不要求 fast-forward；旧对象失联则显示不可读/待核对，不查分支最新内容冒充原确认。要求 Git 管理方配置保护分支并核证，但平台自身仍验证身份与内容。
5. **权限与两种确认清晰分开（R7-002/006）。** 确认写入同时核可信委员会资格和当前仓库 read，历史展示逐主体核权，缓存不能带来授权。UI 分列委员会确认与 MR 审阅；所确认 commit 全长可见，并分别展示当前浏览版本，不能只用绿色徽标掩盖版本关系。普通 MR 变更没有新增委员会确认门。
6. **只追加历史（R7-007）。** 新版本再确认是新事实，旧失效原因保留。它不写 Git 文件、不勾 tasks、不改变发布状态，后续状态机只可引用事实，不能反过来伪造确认。

## Risks / Trade-offs

- 保守文件判定可能把排版误作实质修改；语义判定又可能漏失效。PM01 已批准，据此固定验收数据集，不能靠 AI 在线自由判断自动保留确认。
- Git 事件会漏、对象可能被回收：任何新版本作为有效依据前均需重核，不仅依赖 webhook；轮询/对账频率和事件时延需 prodops 给事实后评审，不承诺未核的 SLA。
- 权限与资格映射未核实：失败关闭，不能退回服务账号权限；R7-A01 为实施前置条件。

## Migration Plan

规格冻结审阅 → PM01 与 prodops 事实回写 → 授权实施 → 正反场景及真实 Git/主体独立验证 → 预发另申请 GO。现有旧确认不转换成新 Git 确认；新功能撤回时保留审计事实并明确功能不可用，不恢复旧 Spec 编辑或重绑历史。没有数据库 DDL 或上线动作。

## Open Questions

R7-PM01 已批准；提供方与 R7-A01～03 事实仍待核，严格校验不代表真实 Git/ACL 或完整产品验收。


## 本轮授权实现边界（R7 部分实现）

- 依据组长 2026-11-01 对 4b39991c 规格 PASS 后的实施单，只实现无托管提供方读取依赖的部分。R7-PM01 已于 2026-11-01T02:23:43Z 批准 A 和三类豁免，本次追加实现但保持关闭；R6 提醒实现不在本单。
- `internal/specconfirm` 提供确认事实、坐标校验、服务和可替换 `ChangePolicy`。`ConservativePolicyA` 按 v2 保守比较 Markdown 并仅排除已批三类变化（详细边界见追加决策），`PolicyApproved` 零值 false；无环境变量、CLI 或 HTTP 接口能开启它。默认不执行 Git 比较；同一完整 SHA 只表示该原版本已确认，不同 SHA 统一待核对。测试中的策略启用仅验证已批准算法，不代表运行时激活或真实提供方验收。
- `Authority.WithAccess` 是启动时注入的可信依赖，必须核受控仓库、该 commit/变更存在性、主体当前仓库 read；确认写入额外核委员会资格，并在回调内保持授权有效。不能用旧 management/owner 角色、Git 作者或服务账号读权限替代。当前主程序不注入此依赖，也不读取任何真实托管提供方；真实记录读写返回 503，Console 不下发未就绪入口。测试使用独立模拟授权器与真实隔离 SQLite，不声称已验证真实托管提供方 ACL。
- 接口：`GET /console/openspec-confirmations` 为单独 Console 页面（R7-002/006）；`GET /api/console/openspec-confirmations` 以 git_instance、repository、change_dir、commit_sha 查询该变更历史及相对该明确 commit 的版本关系（R7-003～006）；`POST` 同路径只收上述固定坐标、operation_id 与 meaning（R7-001/002/007）。全部走既有可信 Console principal 中间件，确认人由会话取得，时刻由服务端生成，拒绝未知字段/额外 JSON/分支名/短 SHA/路径混淆。缺失身份/资格/ACL 依赖不放行；依赖详情不出服务端。
- API 的 400/403/409/503 分别表示无效输入、无权、操作事实冲突与依赖不可验证，对应 R7-001/002/004/006/007 的拒绝边界。POST 限 JSON、16 KiB，并检查跨站来源；历史最多 500 条，超过整体报依赖不可用而不静默截断。此上限是本轮有界读取保护，分页历史体验后续另评审，不能伪造「全部历史」。
- `openspec_commit_confirmation` 记录独立审计事实，不与旧 Spec 或平台 principal/project 设置级联外键。主键由可信主体与操作编号确定；事务内 insert-if-absent 后比对完整原事实，同操作改坐标/含义拒绝，重试保留原时刻；新版本再确认追加新操作。数据库触发器拒绝 UPDATE/DELETE（R7-001/005/007）。
- Console 以 textContent 展示原确认的全长 commit、当前浏览 commit、确认人/时刻/含义及比较依据，单独列出 MR 审阅；加载响应有代际校验，避免异步旧结果套到新坐标。入口仅在可信服务依赖装配后下发，可见性不授予委员会资格（R7-002/006）。
- 本轮不做自动 Git 监听/对账、真实读取/ACL 接入、比较判定的持久审计/批量重判、完整 R7 生命周期或 R6。`Assessment` 返回两端 SHA/策略版本/原因，启用自动比较前还必须补比较审计持久化与真实 Git 反例验证；不能把此部分交件标作全部 R7 场景 PASS。

## 发布注意

- 本分支仅新增 `0068_openspec_commit_confirmation.sql`，预留独立 R11 冻结分支的 0067，不复制或改写 0067。以本分支独立迁移 SQLite 账为 65→66；与 R11 两条迁移一同集成则为 65→67。集成负责人须按实际发布树调整控制器/manifest 的 MIGRATION_COUNTS，并验证 0067/0068 顺序与回退；本单不改发版版本号或发布控制器。
- 0068 在表、索引、两条保护触发器均存在且定义相同的无账库上只补账；有残缺或定义不同则拒绝，不能用 IF NOT EXISTS 掩盖保护缺失。迁移与账同事务；已有账 digest 检查沿原执行器。不触碰原确认内容。
- 旧二进制的迁移遍历规则忽略额外账项，不会消费新确认表；撤回 R7 入口不删除新表/历史。不在本单执行 DROP TRIGGER、删除记录、生产迁移、部署或重启。R11 仍固定 5c0fce04。

## 已批准策略追加实现（业主 2026-11-01T02:23:43Z，组长本次追加单）

- 新策略版本 `A-conservative-exemptions-v2`：仅根 tasks.md 的真实任务 checkbox 状态和「交接记录」节正文豁免；任务文字/编号/增删、其它文件、代码围栏/缩进代码中的示例仍计实质。交接节保留原标题，遇同级/父级标题恢复比较，避免吞掉后续任务。重复交接标题、未闭合围栏、HTML/setext 歧义采用保守原字节比较，不启用额外排版白名单。
- 活动目录到同提供方/同仓/同变更编号的合法日期 archive 路径，可对完整文件集合逐个相对路径比较；只有所有字节完全相同才豁免。移动同时勾选或修改交接仍非“内容不变”，计实质；不同日期归档间移动、反向 unarchive、跨变更/仓库/提供方不可推定等价，显示待核对。
- `Assess` 支持上述明确的活动→归档坐标对，仍保留原确认坐标和两端 SHA；不通过改变 `SameChange` 或数据库查询做目录/仓库别名。当前历史列表仍只查询请求的原目录；归档前后历史发现/对账由后续真实提供方集成补齐，本单不声称完整归档生命周期已实现。
- `SnapshotReader` 明确为仓库托管提供方接口，`Authority` 由选定提供方适配器装配。工蜂转 GitHub 未定，主程序不装配真实读取/委员会/ACL 依赖。`PolicyApproved` 仍默认 false，无环境/CLI/HTTP 激活通道；切换日另行授权装配，当前不同 SHA/目录无读取即待核对。
- 上方“本轮授权实现边界”记录 fb2251f9 当时交件；PM 状态及算法说明已按本次追加单更新。完整权限事实、比较审计、真实 Git/全场景与预发仍待后续，迁移和发布配置本单不动。
