# Proposal

## Why

Git 分支可前移或被强推，若确认只挂在变更编号或分支名上，规格内容改变后仍会被误读为委员会已认可。旧 Spec 的修订与正文摘要也不能代替仓库 commit，因此需要可审计的固定版本确认、旧版本失效标记，以及与普通 MR 审阅明确区分的界面语义。

## What Changes

- 新增绑定仓库、变更目录、完整 commit、确认人、UTC 时刻与确认含义的委员会确认。
- 需求、场景、范围或任务实质改变后失效并显示「针对旧版本」；强推不迁移记录，比较失败不冒充仍有效。
- Console 持续显示所确认 commit，确认不替代 MR 审阅、不新增普通变更必点确认门。

## Capabilities

### New Capabilities

- `console-version-confirmation`：新增 R7-001～007；同目录最小基线只描述旧记录语义，不声称新功能存在。

### Modified Capabilities

无。

## Impact

仅规格与最小基线/context；未来涉及 Console、授权、Git 坐标验证、确认审计存储和版本比较。无新 API/数据库迁移/产品代码，不修改 R11 分支或开启冻结。普通 MR、R8 状态机、R9 多渠道 PM 回应、部署授权不在本单实现。

## 待确认假设

- R7-A01 由 prodops 核实稳定仓库 ID、完整 SHA 可读性、逐主体仓库 read 与委员会确认资格的可信映射；平台角色不得冒充仓库授权。未核实不得实施放行。
- R7-A02 由 Git 管理方核实保护分支配置及强推/删除事件、漏事件后的对账方式；分支保护仅纵深措施，不能替代按 SHA 绑定。
- R7-A03 旧审阅表不直接复用为新委员会确认；持久化接口、实际代码位置与一致性机制实施前另行评审。本规格不宣称这些已存在。

## 待 PM 决策
