# Proposal

## Why

Console 会话回放目前依赖 Hub 进程内的结构化事件环，历史按事件帧封顶，既没有按消息或回合保留的持久化记录，也不能在进程或 helper 连接重建后继续读取。环一旦被清空，数据库中已有的投递记录并不能供回放使用；活跃会话还会在达到帧数或字节预算后截断。该变更拟把 Agent 会话历史变为有界、可授权、跨重启读取的记录，并明确游标连续性、清理与隐私边界。

## What Changes

- 为每个 Agent 增加有界的结构化会话历史持久化，以消息／回合为保留单位，不按 SSE/WebSocket 帧计数；业主口径为最近 1000 条，最终保留单位与上限仍列 PM 定值。
- 让 Console 回放从持久化记录和稳定游标读取，并与现有 eventRing 实时流衔接，避免 Hub 重启、helper 重连造成重复或静默缺失；明确历史已淘汰时的 gap 与 resync 行为。
- 明确持久化存储、写入时机、热路径影响、条数／字节／时长限额、授权可见范围、撤权删除、加密、迁移和回退方案。
- 不把 `session_delivery` 或 `message` 现存记录直接视为完整会话历史；不回填无法从现有数据重建的事件；不在本变更中执行迁移、部署或生产／预发操作。

## Capabilities

### New Capabilities

- `console-session-history`：有界持久化 Agent 会话历史及跨重启回放。

### Modified Capabilities

无。

## Impact

候选实现涉及 `internal/m8` 的结构化事件接收、Console mux／View 回放协议，以及 `internal/store` 的 SQLite schema 与读写。写入会增加事件接收热路径的数据库或队列工作；持久化原始会话内容会增加磁盘占用和隐私责任。具体存储和协议尚待 PM 决策，本提案不规定未经批准的生产数据迁移或保留行为。

## 需求来源

事实基线：[S-HISTORY-EMPTY-FACTS 只读报告](https://git.code.tencent.com/wego-ai/dingwei/blob/1c7cc1e29/docs/reviews/prodops-history-empty-facts-20261102/REPORT.md)，提交 `1c7cc1e2`；仓库代码锚点为 `c248506cf120c3af2a06eeaeeae3038f596537b1`。业主派单口径：每 Agent 按消息／回合而非帧保留最近 N 条，默认口径 1000，并要求本提案列明实现候选、PM 点与验收场景。

## 待确认假设

- 假设产品所称“Agent 会话历史”指 helper 上送且 Hub 当前会进入结构化 `session_event` 的内容；它不自动覆盖旧 `terminal_output` 原始终端帧或未到达 Hub 的本地事件。
- 假设 Console 仍通过现有 Agent 所有权和会话授权检查后读取历史，不因持久化而扩大至平台管理员或其他 Agent。
- 假设历史淘汰或游标无法连续时仍必须显式报告 gap；是否可对单纯 Hub 重启免显式 resync，需由协议设计及 PM 定值确认。

## 待 PM 决策

1. **PM-R15-01：保留单位与 N。** 选项 A：单条 Hub 接收的结构化会话事件，最近 1000 条（推荐，能精确对应现有事件流）；选项 B：按完整用户／Agent 往返回合计 1000 条（语义更贴近对话，但需定义多消息、未完成回合与工具事件归属）。建议 A，先确保 Hub 已接收的每条结构化事件都有稳定序号和去重键；回合视图可在读取层聚合。
2. **PM-R15-02：单条体积与总容量。** 选项 A：单条 256 KiB、每 Agent 16 MiB／1000 条、Hub 全局 128 MiB（推荐，沿用现有 ring 预算并加硬上限）；选项 B：按预计流量扩大预算。建议 A，避免持久化绕过当前 eventRing 的字节保护；超限策略应丢弃最旧记录并报告 history gap，不截断单条后伪称完整。
3. **PM-R15-03：保留时长。** 选项 A：最多 30 天并受条数／字节上限共同约束（推荐，平衡短期复盘和数据最小化）；选项 B：只按数量／字节淘汰，不设 TTL。建议 A，并要求过期清理由后台有界批次执行。
4. **PM-R15-04：谁可见。** 选项 A：仅该 Agent 所属账户下通过现有授权的 Console 会话可见（推荐）；选项 B：另授平台管理员跨 Agent 查看权限。建议 A，持久化不应自行扩权。
5. **PM-R15-05：撤权／删除。** 选项 A：Agent 凭据撤销、所有者删除或身份解绑时立即删除对应历史及索引（推荐）；选项 B：保留到 TTL 到期。建议 A，撤销后不保留可关联的会话正文；操作审计仅保留不含正文的最小元数据。
6. **PM-R15-06：静态加密。** 选项 A：由部署卷／数据库层加密保护，并核验其覆盖备份（推荐，先复用既有运维机制）；选项 B：应用层字段加密并新增密钥轮换／恢复流程。建议先选 A；若部署层不能证明覆盖主库与备份，应暂停正文持久化上线并另行批准应用层密钥方案。
7. **PM-R15-07：工具调用细节。** 选项 A：保存当前结构化事件原文，包含工具调用／结果等已上送字段（推荐作为兼容行为，但需采用 PM-R15-06 的保护与同一删除策略）；选项 B：默认剔除工具输入／输出或仅保存摘要。建议 A 可维持既有回放语义；若工具正文含敏感数据，需在实现前由业主定脱敏规则，不能由开发席自行改变事件含义。
8. **PM-R15-08：Hub 重启后的 resync。** 选项 A：cursor 使用持久化的 Agent 序号／历史代际，纯进程重启时无 gap 且免显式 resync；仅淘汰、身份代际变化或不可修复缺口时要求 resync（推荐）；选项 B：重启仍一律 epoch_changed 并显式 resync。建议 A，避免把可连续的持久历史误报成丢失，同时保留真实 gap 的完整性提示。

## 验收范围

本提案列出的场景仅定义未来实现的验收标准；本单不执行任何用例，不迁移或删除现有数据，也不触碰现网／预发。
