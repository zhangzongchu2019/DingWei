# Proposal

## Why

切换后任务必须来自仓库tasks.md的固定任务编号，现有数据库旧任务分配不能证明某仓库某变更某个T编号只有一个执行者。若把commit也放入互斥键，同一任务可因版本不同而同时派给两人；租约到期后若不识别旧代际，迟到请求又可能释放或污染新持有者的锁。需要复用R5的受权固定版本读取，在平台保存坐标、互斥租约与交接审计，明确规格变化和跨仓边界，不把任务勾选、消息送达或过期回收误认为工作已完成。

## What Changes

- 新增task-dispatch-lock能力R10-001～009：固定任务坐标、逐主体读取、跨版本单任务互斥、到期/续租、主动释放、原子交接、规格漂移、跨仓隔离与派单审计。
- 平台只读tasks和交接，保存锁/派单元数据，不回写勾选或保存Agent上下文正文；派单仅发仓库、变更、T编号、完整commit等坐标。
- 新能力按现有源码补主规格最小基线及context；增量仍是未来行为。本次只有提案，不实现，不激活、不改r46集成或其它已冻结分支。

## Capabilities

### New Capabilities

- `task-dispatch-lock`：按仓库稳定身份＋规范变更目录＋T编号互斥，commit只标所派版本，不进入互斥键；锁有可信持有者、起止/到期/释放时刻、代际和交接记录。

### Modified Capabilities

无；复用R5读取与R7已批比较策略，不修改旧任务、R7确认或R8推进契约。

## Impact

后续实现涉及R5只读适配、Console/Agent主体与派单资格、独立锁存储/事务、可靠派单通知、规格漂移检查及锁展示。旧console_spec_task的UUID、assignment_version与本能力T编号/锁代际不混用。平台锁只能拒绝旧持有者的平台操作，不能撤销离线Git写权限或保证不合作客户端停止编码；执行席需在过期/漂移时停工并在提交前重核，实际代码合并仍走MR。测试只在隔离环境；不增加任意URL/SSH读取、不创建新源码交换渠道。

## 待确认假设

- R10-A01：R5受控提供方/仓库具备稳定仓库ID、完整固定commit读取和身份映射。r46仅实现GitHub适配，工蜂适配不可用；本单只推工蜂不代表产品已能从工蜂API读tasks，缺适配时失败关闭。
- R10-A02：派单人有可信派单资格，受派Agent有独立R5可验证主体与仓库read。目前R5 Binding.Valid针对github/Console principal，未证明Agent映射接线；不借派单人或服务账号授权兜底，列实施前置。
- R10-A03：锁存储能以唯一键/事务CAS跨进程串行授予且提供可靠服务端UTC；迁移方案、重启恢复、通知outbox及同一权威时钟须实现前实测，不假定已有新表或接口。
- R10-A04：提供方能读取跟踪MR当前head或显式选定分支ref并比较完整快照；事件推送、API容量与时延未核。不确定比较必须标待核，提交重核不能由轮询替代。
