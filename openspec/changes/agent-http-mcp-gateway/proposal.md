# 提案

## Why

目前未在平台注册的外部 Agent 无法作为 DingWei 席位参与 Hub 通讯；现有接入依赖本机 sessionHelper 与其 IPC，无法满足其他厂商或自研 Agent 通过网络轮询收发消息的场景。本变更设计一条受限的 HTTP 接入能力，使业主能按账号和编组授予、审计并撤销通讯权限，同时沿用现有投递与确认语义，且不开放执行、宿主访问或升级能力。

## What Changes

- 定义与 helper 席位并列的 HTTP 席位身份、在线租约、收件队列及确认映射。
- 提出 Hub Streamable HTTP MCP 服务和能力等价的 REST 接口；两者只提供在线清单、发消息、有限长轮询收件与确认。
- 定义每席位令牌、授权范围、吊销、限流、审计、提及解析、离线排队和过期策略。
- 分期交付单编组 MVP，并列出后续扩展、验收判据、测试与变异测试。

## 需求来源

业主派单与 ruling ㊹：[S-TEAM-MIGRATE-HOSTED-20261017.md，commit f4085c32](https://git.code.tencent.com/wego-ai/dingwei/blob/f4085c32/docs/rulings/S-TEAM-MIGRATE-HOSTED-20261017.md)。

## 范围与影响

本变更仅新增 OpenSpec 设计提案，不改产品代码、数据库或现有席位行为。实现若获批，将在 Hub 增加 HTTP 席位及两种等价传输；sessionHelper、send.py 和 helper 席位继续使用现有路径。MCP 规范依据见设计文档；当前 Hub 是否已有可互操作的 Streamable HTTP MCP 服务及 OAuth 资源服务器能力：未核实。

## 待确认假设

- 单编组 MVP 的外部席位由管理员预先创建并绑定现有账号和一个编组；不开放自助注册或跨编组寻址。
- 每席位使用服务端生成的 opaque OAuth access token；数据库只保存安全哈希，明文只在创建或轮换时展示一次。
- 离线入站消息保留 24 小时，超期转为 dead 并向发送方给出可查询的失败状态；该时限为提案默认值，须由业主确认。
- 在线租约由成功认证的轮询/收件请求刷新，连续 90 秒无活动视为离线；长轮询等待上限 25 秒，均为提案默认值，须由业主确认。

## 待 PM 决策

1. 令牌生命周期：A. 管理员预置 opaque OAuth access token（建议，MVP简单且可吊销）；B. 完整交互式 OAuth 授权码流程（标准体验更完整，实施较大）。建议 MVP 采用 A，但仍实现 MCP 规范要求的 OAuth 资源服务器发现与 Bearer 校验。
2. 离线队列保留期：A. 24 小时（建议）；B. 7 天；C. 按编组配置。建议先用统一 24 小时并提供配置。
3. 在线判定：A. 90 秒无成功请求即离线（建议）；B. 由长轮询周期推导；C. 采用独立心跳端点。建议 A，长轮询请求本身续租。
4. 外部席位名称：A. 使用现有全名语法并纳入普通在线清单；B. 独立命名空间并在清单中标类型（建议，减少重名及误认）。
5. 提及外部席位：A. 沿用现有提及解析并允许编组内提及；B. MVP 仅允许显式全名，后续扩展（建议，限制初版广播范围）。
6. MCP OAuth 最低实现范围：A. MCP 要求的受保护资源元数据、标准 OAuth Bearer 验证与预置客户端（建议）；B. 先提供非标准静态 Bearer token、之后补齐 OAuth。B 不符合 MCP HTTP Authorization 规范，不建议。
