# Console Timeline Order

## Purpose

本变更把 Console 时间线从按事件到达顺序追加改为按卡片发送时刻定位，目的是使迟到接收确认的用户输入仍显示在对应回合回复之前。涉及 View renderer 的首次渲染、刷新历史回放与向上分页，不影响 Hub 投递协议、事件正文或其他会话授权行为。

## ADDED Requirements

### Requirement: R51-TIMELINE-001 时间线按发送时刻定位消息

Console MUST 使用统一定位规则将带发送时刻的用户输入、Agent 回复和历史节点按发送时刻升序放入时间线。待提交输入在回合输出之后收到接收确认时，转为正式用户卡后仍 MUST 位于该回合输出之前；刷新重建和向上历史分页 MUST 保持同一顺序。缺少发送时刻的节点 MUST 保持稳定回退顺序。

#### Scenario: R51-TIMELINE-S001 活动回合接收确认晚于回复

- **WHEN** 用户输入先进入待提交区，Agent 回合输出到达，之后才收到该输入的接收确认
- **THEN** 用户卡在同回合回复之前，且页面显示原有的用户文本和回复文本

#### Scenario: R51-TIMELINE-S002 刷新重建顺序

- **WHEN** 页面刷新并按相同事件序列从会话历史重建时间线
- **THEN** 用户卡仍在对应 Agent 回复之前

#### Scenario: R51-TIMELINE-S003 空闲发送保持顺序

- **WHEN** Agent 空闲时先有一条既有回复，再收到并确认用户输入
- **THEN** 既有回复仍在用户卡之前

#### Scenario: R51-TIMELINE-S004 历史分页采用相同定位规则

- **WHEN** 向上分页回放较早事件且时间线中已有实时事件
- **THEN** 新历史节点按发送时刻插入，历史与实时节点的可见顺序稳定，原可视锚点保持不变
