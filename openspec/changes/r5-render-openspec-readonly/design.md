# Design

## Context

现有数据库旧 Spec 读取、公共 Markdown 渲染与共享 capability 见能力 context。本次 R5 阅读源换成受权仓库托管提供方仓库固定 commit；GitHub API 事实按 e8b14b69 回写，真实绑定与令牌完整范围仍未核。R5 读取器与旧格式写入口分开，不复用旧共享链接的授权语义。

## Goals / Non-Goals

- 目标：在读取、缓存和呈现三个边界落实 CSR-001～007。
- 边界：不创建 Git 写回接口、不实现派审、确认、PM 决策、状态机或任务锁；不把 OpenSpec CLI 嵌进 Hub 构建链。本轮授权实现 T-03～T-06；真实权限验收与预发 T-07/T-08 另单。

## Decisions

1. **坐标先解析再读取（CSR-001、004）。** 阅读请求的逻辑输入是受控仓库稳定 ID、完整 commit、允许范围内路径。ref 仅作为用户选取版本的输入，解析后丢弃其作为读取身份的资格；tree/blob 响应需要核实际来源。不接受任意 raw URL 或平台代抓地址。相比直接加载可变分支链接，可避免同一阅读会话混入不同版本。仓库托管提供方具体 endpoint 与字段由 R5-A01/A03/A04 核实后补映射表，不在此虚构新 API。
2. **逐主体核权再放行任何内容（CSR-003）。** 逻辑顺序为 Console 身份→可信仓库托管提供方主体映射→当前仓库 read 证明→tree/blob→呈现。服务凭据留服务端受控管理，不能直接发浏览器；缓存仅能复用内容字节，不能复用别人的授权。权限不可验证时失败关闭，相比仅用服务账号/平台成员名单不会扩大私库可见范围。账号绑定由管理员维护，逐次核 read，scope 缺口不冒认已闭合。
3. **受限文档树和渲染策略（CSR-002、004、005）。** 首期按 R5-PM02 已批方案，仅允许 `openspec/` 内普通 Markdown；拒绝 symlink/submodule，不取任意附件。相对链接先以仓内文档路径归一，再验证允许范围；不是一见 `..` 就拒绝合法的同范围父目录引用。禁止 HTML 执行、危险链接和所有自动图片请求；外链只经用户主动访问。相比无条件复用旧渲染器，独立策略不放宽其它页面，也不会把仓库文本提升为受信 DOM。
4. **缓存与失败不冒充事实（CSR-001、003、006）。** 内容身份至少包含实例/仓库/commit/path；授权检查不因缓存命中省略。页面切换主体或坐标时清除旧结果状态；失败时不把旧内容标为本次成功。对已送至获权浏览器的内容无法事后收回，撤权保证作用于下一次服务请求，不承诺抹去用户已读信息。失败分类遵循 CSR-006 的可见原因，不先发明未评审 HTTP 错误码。
5. **只读展示不产生完成证明（CSR-007）。** tasks 勾选以原文件内容呈现，不接入旧 Spec 签核表；archive 目录只是来源路径，不能自动推导发布。R6/R7 将来使用本读取的不可变坐标，但它们的新增流程需独立增量。

## Risks / Trade-offs

- API 失去当前用户仓库 ACL 查询能力时不接入服务账号兜底，读取立即失败关闭。
- 远程图片禁用影响阅读 → 先替代文本，R5-PM01 若改为同 commit 图片需补规格、授权和资源类型测试，再评审；始终不允许远程自动抓取。
- 配置限额与真实大文档冲突 → 按 prodops API 实测核定并公布，固定单文件上限 2 MiB，至少覆盖 70 KB（另以 70 KiB 验证更强下界），恰好 2 MiB 完整读取、超出显示已批文案和不可变来源链接；不通过消息正文或文件服务交换源码。
- 文档内声明“已确认/已发布” → 只作为仓库文本呈现，不能产生平台确认/发布记录。

## Migration Plan

PM 点已决；先核实 proposal 的提供方接口事实，补实际字段/路径、非单文件限额与凭据管理位置，再实施只读适配、安全呈现和集成测试。经独立审阅及预发后另行申请 GO。若撤回新浏览功能，可停用其读取入口并提示不可用，不回退旧 Spec 编辑模式，不改变仓库内容。

## Open Questions

R5-PM01～04 已按业主答复冻结；R5-A01～06 的提供方接口/权限/非文件资源限额事实仍为前置依赖。未确认之前不能把本设计或严格校验结果解释为可立即实施、已继承真实仓库权限或已完成安全验收。

## R5／R6／R10 共用仓库托管提供方接口（规格契约）

- 逻辑适配接口包括：受控提供方/实例及仓库发现、Console/Agent 主体映射与逐主体 read 核验、ref→完整 commit 解析/归属可读验证、指定 commit 的 tree/blob/类型/分页读取，以及同 commit 来源链接生成；具体 endpoint、字段、限流、错误与 secret 管理位置按提供方核实，不写死工蜂。
- 坐标、缓存和审计身份包含提供方/实例、稳定仓库 ID、完整 commit、路径；更换提供方或同名仓库不能继承旧权限、缓存、审阅或确认，须重新核实映射及对象来源，保留旧事实坐标。
- R6 坐标派审与后续 R10 任务坐标读取必须沿用此接口及独立主体核权，不经聊天或文件服务补源码。当前尚无独立 R10 OpenSpec 变更，不新建任务管理需求；本段是其共享读取约束。
- 首月 Console 用户绑定由管理员维护；按提供方核权不可用仍失败关闭。工蜂转 GitHub 尚未决定；本轮不迁移；只实现 GitHub 与工蜂不可用适配器。

## T-03 实际接口与实现边界

事实逐项见 proposal R5-A01～06，来源 e8b14b69。GitHub 数字仓库 ID 核响应 id；新 full_name 来自按 ID 发现；重定向只在受控 HTTPS API 上处理，内容接口不跨仓跟随。完整 SHA 固定后 tree/blob 不再使用 ref。recursive=1 截断必须完整非递归回退；symlink/submodule 绝不取 blob 或进入子模块。tree.size 先检查 2 MiB，正文同时核实际长度、SHA/摘要与 UTF-8。

读取器位于 internal/specread；无内容缓存、无授权缓存。绑定表 openspec_read_binding 由 platform_admin 维护，审计表记录 actor/旧账号删除与新账号写入；不插入真实行。新页面使用独立 DOM 文本渲染与 CSP，不执行仓库 HTML，不自动创建图片或其它资源元素。源码只通过同 commit 安全 HTTPS 链接由用户主动查看。

配置 DW_OPENSPEC_READ_ENABLED=1、DW_OPENSPEC_GITHUB_CREDENTIAL_FILE（绝对路径、普通受限文件）、DW_OPENSPEC_GITHUB_REPOSITORY_IDS（逗号分隔数字 ID）同时有效才挂服务；默认关闭、Console 不发入口、读取及绑定接口 503。凭据只留服务端、逐次读文件支持轮换，远端错误正文不回显。

本地有界值：API 10 秒、整次 15 秒、并发 4、单响应 8 MiB、tree 10,000 项、非递归回退至多 256 次。逐次读取限速头与 Retry-After；部分 tree 不作完整成功。响应上限/超时/限速/不存在/非 UTF-8/越权分开反馈，不回显旧正文。工蜂无凭据与 SSH 回退，始终不可用。模拟适配器及 HTTP transport 测试不等于真实平台权限验收。

未闭合：完整令牌 scope 未证明、工蜂专用只读令牌未建、现网 Console/GitHub 绑定不存在；T-07/T-08 不在本次交付。

## S-R5-CRED-SYSTEMD：systemd 凭据目录兼容（2026-11-01）

依据组长派单转交的 prodops 18:10:11Z 预发事实：ImportCredential 后文件 root:root 0440，父目录 root:root 0550，ACL 授权 Hub UID 991，进程 CREDENTIALS_DIRECTORY 指向该目录，UID 991 已实测可读 93B。0440 的组位可能是 ACL mask，不能直接等同于组用户有读权限。此为提供方事实，本席未读取真实 PAT，未执行部署或真实 systemd 复测。

仅调整 internal/specread/github.go 的 credential() 安全判定（CSR-003、CSR-006）：环境 CREDENTIALS_DIRECTORY 必须非空、绝对路径，且 filepath.Clean 后凭据路径的父目录与环境值完全相等，才进入 systemd 模型。Lstat 拒绝文件符号链接，必须普通文件；打开后文件属主必须是 0 或当前 euid，权限对其他人没有任何位（&0007==0），组位可表示 ACL mask。父目录 Lstat 必须是目录（不跟随符号链接），属主为 0 或 euid，组和其他人均不可写（&0022==0）。文件描述符元数据与 Lstat 的文件身份用 SameFile 复核；无法取属主元数据即失败关闭。不读取 ACL，也不因 ACL 不可用放宽。

其它任何位置保留原 &0077==0 规则；环境指向别处、相对路径、未设置、非规范目录字符串都不会扩大允许范围。原大小上限、内容校验、逐次重新读取与错误行为不变，提供方调用与逐主体核权不变。未新增功能开关，未改变工蜂失败关闭。实际部署中 CREDENTIALS_DIRECTORY 属 systemd 注入的受控进程环境；本单不修改单元或凭据安装方式。

验证：临时目录与合成 93B，覆盖目录内 0440 接受、目录外同权限拒绝、0444 拒绝、符号链接拒绝、父目录可写拒绝、环境错配拒绝，以及私有文件兼容与轮换/撤回。目标变异禁用新分支后 0440 正格必须断言失败；详见 docs/reviews/r5-cred-systemd/REPORT.md。真实 root:root / UID 991 的修复后运行复测另候预发令。
