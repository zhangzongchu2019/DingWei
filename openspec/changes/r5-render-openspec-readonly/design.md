# Design

## Context

现有数据库旧 Spec 读取、公共 Markdown 渲染与共享 capability 见能力 context。本次 R5 阅读源换成受权工蜂仓库固定 commit；远程 API、身份映射与运行凭据尚待 prodops 核实。R5 读取器与旧格式写入口分开，不复用旧共享链接的授权语义。

## Goals / Non-Goals

- 目标：在读取、缓存和呈现三个边界落实 CSR-001～007。
- 边界：不创建 Git 写回接口、不实现派审、确认、PM 决策、状态机或任务锁；不把 OpenSpec CLI 嵌进 Hub 构建链。本轮只有可审阅设计，未决接口不视作已验证依赖。

## Decisions

1. **坐标先解析再读取（CSR-001、004）。** 阅读请求的逻辑输入是受控仓库稳定 ID、完整 commit、允许范围内路径。ref 仅作为用户选取版本的输入，解析后丢弃其作为读取身份的资格；tree/blob 响应需要核实际来源。不接受任意 raw URL 或平台代抓地址。相比直接加载可变分支链接，可避免同一阅读会话混入不同版本。工蜂具体 endpoint 与字段由 R5-A01/A03/A04 核实后补映射表，不在此虚构新 API。
2. **逐主体核权再放行任何内容（CSR-003）。** 逻辑顺序为 Console 身份→可信工蜂主体映射→当前仓库 read 证明→tree/blob→呈现。服务凭据留服务端受控管理，不能直接发浏览器；缓存仅能复用内容字节，不能复用别人的授权。权限不可验证时失败关闭，相比仅用服务账号/平台成员名单不会扩大私库可见范围。身份、scope 与撤权一致性在 R5-A02/A05 核准前不实施。
3. **受限文档树和渲染策略（CSR-002、004、005）。** 首期按待 PM 审阅的最小方案，仅允许 `openspec/` 内普通 Markdown；拒绝 symlink/submodule，不取任意附件。相对链接先以仓内文档路径归一，再验证允许范围；不是一见 `..` 就拒绝合法的同范围父目录引用。禁止 HTML 执行、危险链接和所有自动图片请求；外链只经用户主动访问。相比无条件复用旧渲染器，独立策略不放宽其它页面，也不会把仓库文本提升为受信 DOM。
4. **缓存与失败不冒充事实（CSR-001、003、006）。** 内容身份至少包含实例/仓库/commit/path；授权检查不因缓存命中省略。页面切换主体或坐标时清除旧结果状态；失败时不把旧内容标为本次成功。对已送至获权浏览器的内容无法事后收回，撤权保证作用于下一次服务请求，不承诺抹去用户已读信息。失败分类遵循 CSR-006 的可见原因，不先发明未评审 HTTP 错误码。
5. **只读展示不产生完成证明（CSR-007）。** tasks 勾选以原文件内容呈现，不接入旧 Spec 签核表；archive 目录只是来源路径，不能自动推导发布。R6/R7 将来使用本读取的不可变坐标，但它们的新增流程需独立增量。

## Risks / Trade-offs

- API 无法可靠查询当前用户仓库 ACL → 不接入服务账号兜底，挂起 R5-A02；依赖核准后才能进入 T-03。
- 远程图片禁用影响阅读 → 先替代文本，R5-PM01 若改为同 commit 图片需补规格、授权和资源类型测试，再评审；始终不允许远程自动抓取。
- 配置限额与真实大文档冲突 → 按 prodops API 实测核定并公布，至少覆盖 70 KiB；不通过消息正文或文件服务交换源码。
- 文档内声明“已确认/已发布” → 只作为仓库文本呈现，不能产生平台确认/发布记录。

## Migration Plan

先解决 proposal 中接口与 PM 待决项，补实际字段/路径/上限与凭据管理位置，再实施只读适配、安全呈现和集成测试。经独立审阅及预发后另行申请 GO。若撤回新浏览功能，可停用其读取入口并提示不可用，不回退旧 Spec 编辑模式，不改变仓库内容。

## Open Questions

R5-A01～06 与 R5-PM01～04 均为显式前置依赖。未确认之前不能把本设计或严格校验结果解释为可立即实施、已继承真实仓库权限或已完成安全验收。
