# Proposal

## Why

飞书私聊中，当前只有一个本人在线可用 Agent 时已经可以免前缀，但有多个 Agent 时每条消息都要重新指定目标，且候选为顿号连接的短名，无法方便地复制全名继续对话。业主要求保留最近对象三十分钟、显式切换优先、过期候选将上次对象排首并逐行带井号。本变更先冻结身份、时钟、不可用回退与复制语义，避免为了便捷而猜错目标、越属主或意外广播。

## What Changes

- 新增`feishu-agent-sticky`能力，9条需求R14-001～009；仅飞书私聊，粘滞键为可信业主账号与机器人BotChannelID，30分钟时长来自业主原话，不在本提案改值。
- 显式指定唯一可用本人Agent后更新默认对象并重置30分钟；无前缀消息在有效窗口续聊；超时或不可用回候选，不静默投给其它人。单可用Agent免前缀沿用，但不能吞掉已知上次对象失效的错误。
- 候选从当前身份权威生成全名，上次仍可选者置首，其余稳定排序；每行`#全名`的纯文本块可整体复制。整个块被原样贴回时的处理另列PM07，建议仅提示选一行，不投首项或广播。
- 本轮只勘察和写规格，不修改源码/主规格/数据库/配置，不apply/archive，不并入在途r47；后续实施与真实飞书验收另派。

## Capabilities

### New Capabilities

- `feishu-agent-sticky`：本人私聊目标选择、30分钟有限续聊、候选可复制格式及隔离/恢复边界。现状与最小基线置于本变更specs/feishu-agent-sticky/context.md，尚无已发布主规格，不把提案当当前能力。

### Modified Capabilities

无。不重写AMR、群聊明确意图门、跨成员授权、系统命令、sync/mirror、现有可靠投递或其它外接渠道协议。

## Impact

未来可能涉及Hub飞书身份解析、L1/默认目标选择、候选渲染与SQLite小状态；现有选择器/归属核验继续复用。具体代码挂点和真实基线证据见context。若批准跨重启保留，需另行设计持久状态与投递/更新失败一致性，不用session_endpoint.last_seen_at代替对话时间，也不把mirror/Agent主动通知当业主选择。真实飞书桌面/移动端复制回入仍须验收；strict/既有构建门只验证结构和旧回归。

## 待确认假设

- R14-A01：首期采用新平台Identity已绑定active业主；“名下”沿用本人owner、实时连接与AgentActive交集，hosted/selfhost均可；同组共享不变成本人默认。旧身份兼容、单Agent计数边界见PM08，未确认不擅自扩权。
- R14-A02：建议将最近稳定Agent ID、时钟锚、绝对到期时间与源消息幂等标识存为独立小元数据；现有SQLite/CAS可作基础，但路由成功与状态更新的一致性仍须实现设计核实，不能冒称已有同事务接口。DB失败不静默降级随机默认。
- R14-A03：代码的纯text发送与JSON提取能保留ASCII井号和换行，但真实飞书复制/富文本粘贴尚未验证；整段复制不等于整段发送即选中全部，PM07须明确。
- R14-A04：建议命中条件为`0≤当前时刻−锚点<30分钟`，恰好30分钟视为过期；消息重放不续期，旧Agent迟到回复不能改掉新选择。计时来源/持久性按PM01/06待批，客户端时间戳不作为可信时钟。

## 待 PM 决策

全部为建议，须业主定值后回写；原话确定的30分钟、显式切换、上次置首及井号格式不重新削弱。

| 编号 | 待定口径与选项 | 建议值与理由 | 冻结前边界 |
|---|---|---|---|
| R14-PM01 | 30分钟从业主最后一条、Agent最后回复或两者较晚开始 | 建议业主最后一条成功受理到该目标的业务消息/成功明确切换，以Hub受理时刻计；Agent迟到/主动回复不替用户无限延长默认 | 精确30分钟过期；不得先把“成功受理”当已注入或已执行；未批准不实施 |
| R14-PM02 | 上次目标离线/停用时，提示候选或选其它可用者 | 建议提示目标不可用并回本人当前候选，停止旧默认，不静默改投；即使只剩另一个也先让业主确认 | 当前派单要求不得静默投别人，建议保持此安全结果；是否保留失效目标历史排序需与PM03配套 |
| R14-PM03 | 候选只含在线active，或还展示离线 | 建议可选列表仅本人在线active；上次离线以独立提示标记，不混入可选块；撤权/换属主不回显旧名字 | 不能将不可用者放首项暗示可路由；若业主要离线目录，另加状态说明且不能自动投递 |
| R14-PM04 | 群聊是否适用 | 建议首期仅私聊，群聊完全沿旧明确意图/前缀规则，不读写粘滞；多人共享群上下文易串话 | 本单已限私聊；任何群聊扩展须业主另定，不默认开放 |
| R14-PM05 | 显式“切换”的指令形式 | 建议保留`#全名 正文`指定并切换；增加裸`#全名`或精确`切换 #全名`作为仅选择、不发空业务消息。普通句子含“切换”不让LLM猜对象 | 仅选择语法、确认文案待批；不把现有parseSelector允许空body当新语义已存在 |
| R14-PM06 | 粘滞跨Hub重启保留或重启清空 | 建议SQLite保留最小目标/时钟元数据，恢复沿原绝对到期时间、逐次重核身份/在线，不以重启重置30分钟 | 未确认不新增表/真实app_config键；若选择不持久须明确提示重启后重新选对象 |
| R14-PM07 | 整段候选被复制并贴回时怎样解释 | 建议可整体复制的逐行纯文本；贴回纯多行候选块只提示选一行，业务投递0、默认变更0，不把首项当选择或把其余行当正文 | 单行`#全名`选择依PM05；不新增广播、多选或自动保存之前未投出的业务正文 |
| R14-PM08 | 单Agent/兼容范围按登记总数还是本人可用在线数；旧身份是否新增粘滞 | 建议沿当前新平台本人在线active计数，hosted/selfhost不区分、不纳他人共享；旧平台维持原分发不新增粘滞。已知旧目标不可用按PM02优先，避免唯一其它对象被误投 | 候选NoDirectory/producer不另创筛选规则；若需改变当前本人计数口径须业主明确，不把Console总登记数当在线数 |
