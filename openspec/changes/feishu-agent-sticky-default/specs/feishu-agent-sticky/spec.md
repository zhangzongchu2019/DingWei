# Feishu Agent Sticky Default

## Purpose

本变更把飞书多 Agent 私聊每条都需显式指定的选择方式，改为按业主账号和机器人通道隔离的三十分钟有限续聊及可复制候选，目的是减少重复输入并避免过期、离线或歧义时误投。涉及 Hub 私聊路由、身份校验和目标元数据，不影响群聊、AMR 或其它渠道的既有规则。PM01～08已按proposal冻结；这仍是提案规格，不表示已经实现。

## ADDED Requirements

### Requirement: R14-001 私聊身份与键隔离
系统 MUST 仅在飞书私聊使用粘滞，以可信Identity业主账号与BotChannelID为键；MUST NOT 用正文指定的属主、全局最后对象或群聊上下文替代。未绑定、停用或无法确认身份时 MUST 拒绝默认选择，不读取或改变其他键；旧身份兼容范围按已定PM08。

#### Scenario: R14-S001 账号与机器人隔离
- **WHEN** 业主甲在机器人一选A，随后业主乙在机器人一或甲在机器人二发无前缀消息
- **THEN** 后两键不继承甲/机器人一的A，也不修改其目标或到期时间

#### Scenario: R14-S002 身份失效不借旧默认
- **WHEN** 原已绑定账号被停用或本次身份解析失败
- **THEN** 无业务消息投到旧默认或其它Agent，不泄露其他账号候选，不更新粘滞

### Requirement: R14-002 本人当前可路由集合
系统 MUST 按当前本人owner、AgentActive与实际在线连接交集求可路由目标，逐次核权；共享/同组他人、离线、停用、撤销不得成为隐式默认。hosted/selfhost及单Agent计数按已定PM08；展示全名 MUST 来自当前身份权威，稳定目标身份不得仅靠可重用名字。

#### Scenario: R14-S003 同组他人不计入本人
- **WHEN** 本人A在线，另有同组其他属主B在线且可通信
- **THEN** 本人默认集合只含A，不能因共享可见将B纳入本人默认或粘滞

#### Scenario: R14-S004 离线与停用重核
- **WHEN** 名下B离线或被停用，即便旧连接记录/数据库Active尚未清理
- **THEN** 本次可路由集合不将B视作可选活跃目标，不能根据历史端点状态绕过身份核验

### Requirement: R14-003 显式指定优先且成功才切换
系统 MUST 保留既有命令优先级；私聊中消息开头的井号短名 MUST 先在本人Agent短名中精确匹配，再对本人短名作唯一前缀匹配；多候选 MUST 返回候选而不猜。井号全名 MUST 按全名匹配，可指向其他用户Agent，但仍须通过既有跨成员授权和归属核验。井号名只能在消息开头生效；只写井号名无正文时仅切换、业务投递数为0，不设“切换”关键词。成功受理业务或仅切换后改变默认并重置30分钟。显式歧义、不可用、外属主或受理失败 MUST NOT 静默回退旧默认或修改时钟，且不得向Agent发送空业务正文。

#### Scenario: R14-S005 明确切换替代旧目标
- **WHEN** 有效默认为A，业主按获批语法明确选可用B并成功受理
- **THEN** 本次正文仅按原路由给B，默认改为B并从成功事件重置30分钟；仅选择形式的业务投递数为0

#### Scenario: R14-S006 无效或歧义不回退
- **WHEN** 业主明确目标有多个命中、无权限、不可用或路由失败
- **THEN** 清晰返回对应失败/候选，不投旧A、不自动投其它Agent、不切换或续期

### Requirement: R14-004 三十分钟有效期与时钟归属
系统 MUST 在有效默认仍可路由时将普通无前缀私聊续给该对象，时长固定30分钟；按已定PM01，Hub成功受理的业主消息/明确切换时刻续期，`0≤now−锚<30分钟`有效、等于30分钟过期；Agent迟到回复、ACK、提示、系统通知和重复消息 MUST NOT 擅自改变目标/续期。时钟异常不可延长旧默认。

#### Scenario: R14-S007 窗口内外边界
- **WHEN** 按PM01时钟且默认A可用，分别在锚后29分59.999秒和30分整收到普通消息
- **THEN** 前一独立格只路由A并依策略续期；后一独立格在多Agent时返回候选而不投递或自动续期

#### Scenario: R14-S008 迟到Agent回复不夺回默认
- **WHEN** 业主已从A切到B，A的旧回合回复或旧消息重放随后到达
- **THEN** 默认仍为B，A旧事件不覆盖目标、重置B时钟或使已过期默认复活

### Requirement: R14-005 超时不可用回候选且不误投
系统 MUST 在多Agent默认过期、没有有效选择或目标不可用时回本人候选并提示原因，不静默投别人。已知原目标失效时即便只剩另一个可用Agent，也按已定PM02先请求明确选择；无法核权/读取状态时 MUST 失败可见，不用空记录伪造首次默认。候选不缓存业务后自动重投。

#### Scenario: R14-S009 原目标失效而其它目标唯一
- **WHEN** 原默认A离线/停用/撤权而B成为唯一在线Agent
- **THEN** 按已定PM02/08的拒绝误投策略回候选，本次不静默给B；选择B后也不自动补发上一条未发送正文

#### Scenario: R14-S010 无目标或存储失败
- **WHEN** 本人没有可用Agent，或身份/默认状态读取失败
- **THEN** 明示无可用目标或暂不可确定，业务投递数为0，不跨账号回退或任意选择

### Requirement: R14-006 上次置首与可复制候选
系统 MUST 把当前仍合法可选的上次对象置于候选首位，其余按全名稳定排序；每行ASCII井号紧接实际全名，无编号/旧后缀，可整体复制。离线展示按已定PM03，不泄露已撤权身份。纯多行候选块回贴按已定PM07仅提示选一行，MUST NOT 自动选首项、广播或把其它候选行投成正文；单行选择按已定PM05处理。

#### Scenario: R14-S011 过期候选顺序与格式
- **WHEN** 业主上次与B对话，窗口过期且当前本人A/B/C都可用
- **THEN** 候选首行为#B的当前全名，其余全名稳定排序，每行均可原样复制，没有自动投递或刷新时钟

#### Scenario: R14-S012 纯候选整块回贴
- **WHEN** 业主把本功能纯候选多行块整体复制并贴回，且采用已定PM07方案
- **THEN** 仅回选一行提示，目标投递数0、默认变更数0；不把首项后的行当业务，不触发AMR或群发

### Requirement: R14-007 保留单 Agent 免前缀
系统 MUST 保留私聊唯一可用本人Agent免前缀，具体计数按已定PM08；以R14-002集合而非登记总数计数。不含已知旧目标失效后静默改投唯一其它人的情形，须服从R14-005。其它owner/通道的唯一Agent不得被选中，既有命令和明确selector不被该分支吞掉。

#### Scenario: R14-S013 唯一可用对象免前缀
- **WHEN** 本键无已知失效旧对象，本人可路由集合只有A且普通私聊未指定前缀
- **THEN** 直接受理给A，保持原单Agent便捷路径，无需用户添加#前缀

#### Scenario: R14-S014 登记多个但仅一个在线
- **WHEN** PM08采用本人在线可用计数，本人登记A/B但仅A可用，且不存在需要显式确认的失效旧目标
- **THEN** 本次可走A唯一分支；B登记存在、他人在线或公开目录数均不改变本人计数

### Requirement: R14-008 持久策略幂等与一致性
系统 MUST 按已定PM06使用SQLite跨重启保留；只保存K、稳定Agent ID、锚/原绝对到期、修订及必要幂等元数据，恢复不重新给30分钟且重核身份/在线。同K并发/重放 MUST 不回滚新选择或重复投递；受理/状态更新失败须可见，不能虚报默认已切换。MUST NOT 存对话正文/凭据或用端点last_seen_at当对话时钟。

#### Scenario: R14-S015 重启不重置剩余窗口
- **WHEN** PM06要求持久化，选A后20分钟重启，在锚后30分钟再发普通私聊且有多个目标
- **THEN** 仍按原绝对到期返回候选，不因启动恢复再获得30分钟；读取失败不得猜测默认

#### Scenario: R14-S016 并发与幂等
- **WHEN** 同K明确A/B交错受理，旧A更新晚到，且同源消息被重投
- **THEN** 默认按串行化受理次序保持最新选择，旧修订不能回滚；同消息不重复投递或刷新到期，其它K不受影响

#### Scenario: R14-S019 保存失败不虚报成功
- **WHEN** 目标业务受理与默认状态保存之间注入故障
- **THEN** 结果明确标示默认未成功变更或待对账，后续无前缀不以不确定记录自动投人；恢复按源消息/投递ID对账不盲目重发

#### Scenario: R14-S020 同名重建不继承默认
- **WHEN** A被撤销后新Agent复用其名字，或原对象已换属主
- **THEN** 旧稳定ID不能把新对象或他人对象当成原默认；只有当前合法明确选择才能建立新绑定

### Requirement: R14-009 兼容与可验证结果
系统 MUST 保持群聊、AMR、其它渠道、既有系统/安全/sync/自定义prefix/跨成员规则的语义，不让它们读写私聊粘滞。Agent生成与自备Agent审核两个命名入口 MUST 在提交前查重并明确提示；姓名是 Agent 短名。现有数据库唯一索引仍是并发兜底，旧平台会话名不纳入此约束。候选回复 MUST 沿当前机器人私聊返回，不注入Agent或转成提及任务；记录可追溯源消息、决策类别、实际目标/更新结果，MUST NOT 记录正文/凭据。未来验收须给私聊/通道隔离、时间、失效、复制及重启的正反读数，受理不冒称已执行。

#### Scenario: R14-S017 原有命令与群聊不改变
- **WHEN** 私聊存在有效默认，同时收到系统/roster/sync命令、跨成员明确路由、群聊普通消息或其它渠道消息
- **THEN** 仍按各自既有规则处理，不吞成默认业务，不跨私聊K或更改其目标/时钟

#### Scenario: R14-S018 飞书复制与 AMR 隔离
- **WHEN** 在获授权的真实飞书桌面/移动端复制候选后发送单行获批选择，另用整块回贴及正文Markdown作反例
- **THEN** 单行保持井号与全名并路由到正确本人Agent，整块按PM07不误发、普通正文不被全局改写，系统候选自身不触发AMR/群发；逐格保留回入与实际目标证据


#### Scenario: R14-S021 短名精确与唯一前缀优先
- **WHEN** 隔离验收夹具中同一业主同时在线 active 的短名为 `ts3dev55` 与 `ts3dev5520`，消息开头分别写 `#ts3dev55` 与 `#ts3dev`
- **THEN** 前者精确命中 `ts3dev55`；后者返回这两个候选，不猜、不投递；该场景依据只读存量证据 `review/prodops/r14-shortname-dup-20261102` commit `f44ca5e6a09b2ea6d4dbb61cf869a7e1670a50ca`，环境数据不作为持续不变的实现假设

#### Scenario: R14-S022 全名、消息位置与仅切换
- **WHEN** 开头井号使用唯一短名前缀、完整 Agent 全名或仅有井号名无正文，并另以正文中段井号作反例
- **THEN** 唯一短名前缀按本人 Agent 选择；全名按全名匹配并仍经跨成员授权与归属核验；裸井号名只更新目标且业务投递为0；消息中段井号不触发目标切换，也不存在“切换”关键词语法

#### Scenario: R14-S023 两个命名入口提交前查重
- **WHEN** 托管 Agent 生成页或自备 Agent 审核页输入本人已有（包括 active／suspended）短名并准备提交，且另输入未占用短名
- **THEN** 两入口在请求提交前检查并明确提示重名；重名不发送创建/批准请求，未占用名可继续原有服务端校验；即使并发绕过前置检查，数据库唯一索引仍拒绝冲突
