## ADDED Requirements

### Requirement: R6-001 派审只传不可变坐标
平台 MUST 仅发送受控仓库身份、变更编号和完整 commit SHA 作为派审内容；在发送前验证该 commit 属于该仓库且变更目录存在，拒绝可变 ref、短 SHA、任意 URL、路径穿越与跨仓替换。路由及关联元数据只能用于收件人/请求关联，不得携带正文、摘要片段、补丁、附件、源码下载链接、凭据或授权能力。

#### Scenario: R6-001-S01 合法派审无正文传输
- **WHEN** 发起者向获权 Agent 派审仓库 A、变更 X、完整 C
- **THEN** 消息内容仅含 A、X、C，抓取实际出站信封确认无源码、附件或下载能力

#### Scenario: R6-001-S02 非法坐标和夹带内容被拒
- **WHEN** 请求含分支代替 SHA、跨仓 SHA、缺失变更、穿越路径或额外源码/补丁/下载链接字段
- **THEN** 拒绝派审且无对应出站消息，不用 HEAD 或文件服务补件

### Requirement: R6-002 指派不是授权
发起者 MUST 当前有该仓库权限及派审资格，目标 Agent MUST 独立具备该仓库 read；发送前与接收读取时均核实，权限不可验证时拒绝。平台不得把派审作为授予权限的渠道，不以平台项目关系、同 owner、服务账号或发起者权限代替 Agent 权限，缓存读取同样核权。

#### Scenario: R6-002-S01 两端独立获权后自行读取
- **WHEN** 发起者有派审资格且双方分别可读仓库，Agent 收到坐标
- **THEN** Agent 用自己的获权渠道读取指定 C，平台不转发内容或服务凭据

#### Scenario: R6-002-S02 无权撤权和核权失败均不泄露
- **WHEN** 目标无仓库权限、发起者越权、投递后 Agent 被撤权或 ACL 查询失败（四格独立执行）
- **THEN** 发送前失败不投递，接收时失败不读内容/缓存；所有格均无正文、凭据或下载能力泄露，不自动授权

### Requirement: R6-003 Agent 只审指定版本
Agent MUST 在指定 commit 按 context → spec → 进行中 changes → 平台时间线读取并写回可追溯结论；平台时间线也限于获权记录。指定 commit 或文件不可读时必须报不能审阅，不切换分支 HEAD、不索取他席源码/聊天作为替代。大文档通过 Git 独立读取，不拆消息传输。

#### Scenario: R6-003-S01 分支前移不改变受审版本
- **WHEN** 已派 C 后分支前移到 C2，C 仍可读且文档大于 64 KiB
- **THEN** Agent 完整读取 C 的文档与末尾标记，结论仍绑定 C，没有消息拆分或 HEAD 混读

#### Scenario: R6-003-S02 不可读取不能伪报审过
- **WHEN** C 或必要规格不存在/不可读，只能读到 C2 或聊天摘要
- **THEN** 记录未能审阅及原因，不产生 C 的完成结论，不用替代内容通过

### Requirement: R6-004 结论与时刻绑定审阅事实
平台 MUST 记录仓库、变更、完整受审 commit、可信审阅主体、服务端接收 UTC 时刻、结论和证据位置，并关联原指派；不把传输受理当作审完。提交主体和坐标必须匹配指派；重复同一结果提交幂等，冲突重试不得覆盖原事实；后续修订结论须追加并可追溯。

#### Scenario: R6-004-S01 合法结果及重试可追溯
- **WHEN** 被指派 Agent 提交 C 的结论与仓内/MR/平台报告证据位置并重复同一提交
- **THEN** 只记录一份该结果事实，含可信主体、C 与 UTC 接收时刻，界面可定位证据

#### Scenario: R6-004-S02 错身份错版本和仅受理不算已审
- **WHEN** 其它 Agent 冒交结果、指派 C 却回 C2，或只有投递 ACK
- **THEN** 前两者拒绝且不覆盖记录，ACK 仅为投递信息，所有情况均不标该指派已审

### Requirement: R6-005 超时提醒可检查
平台 MUST 按已冻结的明确截止时刻和提醒周期检查未完成指派，超时向对应审阅人提醒并在 Console 留下提醒时刻与坐标；发送失败可见且不得记作已送达。完成、取消或被新版本替代的旧指派停止原待审催办；重试/重启不得在同一提醒周期制造重复提醒，不因超时自动通过。

#### Scenario: R6-005-S01 到期未审确实提醒
- **WHEN** 使用已批准时限，指派超过截止时刻仍未完成，并重复调度同一周期
- **THEN** 对该人/C 产生一次提醒记录及发送结果，仍为未审，不自动通过

#### Scenario: R6-005-S02 未到期或已结束不误催
- **WHEN** 指派未到期、已完成、已取消或已被替代（四格独立执行），或提醒发送失败
- **THEN** 前四格没有原待审超时提醒；发送失败格显示失败且不宣称送达或已审

### Requirement: R6-006 实质修改使审阅过期并提示重审
受审 commit 之后需求、场景、范围或任务有实质修改，平台 MUST 按与 R7 相同的 PM 策略将原审阅标为「针对旧版本」，显示原 commit 与当前 commit 并向对应审阅人提示重审；保留原结论，不把重审提示当新通过。无关提交不得仅因 HEAD 改变被误标；非实质变化也不改原结论 SHA。

#### Scenario: R6-006-S01 四类修改和迟到结果仍需重审
- **WHEN** C 的结论已到或在途，C2 分别实质修改需求、场景、范围、任务（四格独立执行）
- **THEN** C 结论包括迟到结果只作旧版本记录，Console 显示针对旧版本且对应审阅人收到 C2 重审提示，C2 不算已审

#### Scenario: R6-006-S02 无关提交不误报重审
- **WHEN** C2 仅改其它能力代码且该变更内容已核完全相同
- **THEN** 不产生实质修改重审提示，原结论保持 C，明确其与当前版本的关系

### Requirement: R6-007 强推与未知比较不迁移结论
平台 MUST 保留不可变原坐标及比较依据（两端 SHA、策略版本、原因）；force push 不迁移审阅，原 commit 丢失、比较失败或策略未定时显示「待核对」，不得复用旧结论冒充新版本已审。比较成功的实质变化按 R6-006 标旧版本；分支保护不替代此校验。

#### Scenario: R6-007-S01 强推新内容没有继承通过
- **WHEN** 已审 C 的分支被强推到实质不同的 C2
- **THEN** C 的通过仍留在 C 并标旧版本，提示重审，C2 没有通过记录

#### Scenario: R6-007-S02 无法比较不默认为未改变
- **WHEN** C 已不可读、Git API 不可用或 PM 策略未冻结
- **THEN** 显示待核对并保留原因/原坐标，不以 HEAD、同名路径或缓存通过替代判定

### Requirement: R6-008 逐人可见但不制造委员会确认
Console MUST 对显式指派的多人逐一展示仓库/变更/commit、审阅人、待审/已审/旧版本或待核对、结论时刻及提醒信息。一个人的结果不填充其他人的结果；审阅记录与委员会确认分开，不自动生成委员会确认、合并门、验收或发布状态。查看记录必须继承当前仓库权限。

#### Scenario: R6-008-S01 多人审阅分开呈现
- **WHEN** A/B 被指派同一 C，A 已回、B 未回
- **THEN** Console 显示 A 的结论与时刻、B 待审及其提醒信息，不把 A 结果算作 B 结果

#### Scenario: R6-008-S02 汇总不伪造确认且撤权不可读
- **WHEN** A/B 均审完但无委员会确认，或查看者已失去仓库 read
- **THEN** 前者只有审阅结果，不新增确认/验收/发布事实；后者不返回私库审阅记录，即使有缓存
