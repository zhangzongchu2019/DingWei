# Design

## Context

旧派审把 snapshot 正文放入请求，不能用来承载新 Git 规格。新能力只发坐标，接收者独立取 Git。代码与授权前置事实见 context及proposal的T-03事实回写；本单不修改现有请求协议或上线配置。

## Goals / Non-Goals

- 规定 R6-001～008：坐标派审、权限分离、逐版本结果、超时提醒、逐人展示与改动后重审。
- r44 基本超时提醒在范围内；r46 自动跨组发现、复杂催办升级及 R10 任务单执行锁不在本变更实现。普通 MR 仍是普通变更的正式审阅依据，Agent 派审结果不冒充 MR 通过。

## Decisions

1. **控制面不承载内容（R6-001/003）。** 信封业务内容白名单只有受控仓库身份、变更编号、完整 commit；路由与请求关联元数据只用于投递和结果关联，不成为正文、补丁、附件/下载 capability 或凭据的旁路。变更目录由规范编号定位，服务端验证指定 commit 下真实存在；接收者从 Git 自行读取大文档。抓实际出站消息作为反泄露验收证据，不只检查界面。
2. **指派和仓库授权独立（R6-002/008）。** 发起者身份/派审资格与 Agent 仓库 read 分别核实；发前核权不能代替接收读取核权。无权或核权未知不转发服务账号内容，不代授任何权限；历史记录与平台时间线也需仓库权限。主体映射无法可靠建立时不能进入实施放行。仓库读取/核权使用 R5 的仓库托管提供方接口：按提供方核实身份映射、read、ref→commit、tree/blob 与来源链接；坐标/缓存含提供方/实例和稳定仓库标识，不因工蜂/GitHub 迁移或同名仓库继承权限与结果。迁移尚未决定，本轮不改实现。
3. **固定版本读与写（R6-003/004）。** Agent 按指定 SHA 与 context/spec/进行中变更/平台时间线顺序读取；文档缺失或不可读报告无法审阅，不偷偷用 HEAD。结果关联同一仓库/变更/commit/指派和实际可信主体；保存服务端 UTC 接收时刻，不信客户端可伪造时钟。结论证据可指仓内固定 commit、受权 MR 或平台非源码报告，不把日志/源码正文塞消息。
4. **结果追加与并发（R6-004/006）。** 幂等结果重试只产生一个事实；冲突结果不可覆盖旧事实，修订追加并保持来源。版本在派审后改变时，迟到结果可记原 SHA 历史，不能完成新版本指派。Hub 接受或排队 ACK 仅说明投递阶段，不记录为已审。
5. **比较口径同 R7（R6-006/007）。** 两端 SHA、策略版本与判定依据持久可查；R7-PM01 为唯一政策决策。实质修改令原结论显示针对旧版本并提示对应人重审；已证无关变化不误催。force push 不迁移记录，无法比较或政策未定显示待核对，不沿用绿标。重审提示不是自动同意或新派审结果；旧待审催办停止，针对新版本明确建立指派后按新截止时刻计时。
6. **以打开为终止条件的有界提醒（R6-005）。** 派审时产生逐人 Console 待办，服务端记录指派起点 t0 与可信本人打开时刻；打开不是已审。未打开时首槽 t0+30 分钟，之后按 1 小时安排第二、第三槽，最多三次外发尝试（失败也不回收预算），不升级组长。首期仅现有飞书personal私聊，群通知保持挂起，通过现有私聊通道接入，目标账号可信绑定、接口事实及 secret 位置由 prodops 核实，不擅定或读取凭据。每槽按指派/坐标/审阅人持久化去重，实际出站提交前重核已打开/取消/完成/替代状态；并发打开和调度按服务端提交顺序决定，打开提交之后不再提交新的外发。恢复不补发密集积压，按实际外发时间保证至少一小时间隔；失败可查不冒充送达，重启不重置三次预算。消息体仍仅坐标，不能包含私库正文、标题摘要或凭据。
7. **逐人展示而非新增审批门（R6-008，R7-002）。** Console 显示显式指派名单、各自待审/已审/旧版本/待核对、完整 commit、结果时刻及提醒信息，能一眼找出谁未审。结果与委员会确认分栏，派审不新增合并门，不产生 SPEC_APPROVED、验收、归档或发布状态。后续 R8 另行规范如何消费记录。

## Risks / Trade-offs

- r44 先于 R5 页面：只依赖经核实的仓库坐标/权限底座，不要求只读页面先实现；底座未就绪不得绕过授权取内容。
- 事件漏收、强推或 Git 不可用：使用固定 SHA 重核，任何新版本的已审显示前必须完成比较，不用历史缓存绿标。事件/对账机制及可见时延待核，不能只靠单次 webhook 测试证明长期可靠。
- 催办可能噪声过多：PM02 已固定 30 分钟首催、一小时间隔、最多三次、打开即停；本提醒不升级给组长，不把未打开解释为未完成审阅。

## Migration Plan

完成规格和依赖审阅后才另派实现；无旧正文请求自动转换、无批量导入。先受控 Git 测试仓和独立权限主体验证，再另申请预发；若撤回新派审，保留历史且提示不可用，不回退源码快照发送。无新接口/错误码/数据库 DDL 在本单落地。

## T-03 接口、时限与前置边界

固定e8b14b69事实和5a9cafdd实现见proposal。R6复用R5 Service.Read/Coordinate及逐主体仓库read，按完整C核变更目录和Markdown文件；受控GitHub稳定ID1441460280已测。R5内容获取前及交付前各核绑定/read，但Binding.Valid目前针对github/Console主体；受派Agent映射及派审资格必须另外证明，不能借服务账户读取再转正文。工蜂API适配仍失败关闭，Git ls-remote能用不是产品API已具备；R5默认关闭及T-08前置仍有效。R6产品接口/结果存储、可信打开回执、私聊发送去重/回执待实施另单，本回写不造新端点/DDL/配置。

提醒按当前指派/收件人/固定C/代际计时，t0为持久指派产生UTC。外发槽t0+30、+90、+150分钟，共3槽；同槽使用稳定operation，失败/unknown不换ID或回收预算后无限重发。超三槽、间隔不足1小时、重启重复、停机恢复密集补发均禁止。三槽用尽但未打开时，Console未读待办仍持续，不升级给任何他人。

只有被指派主体经授权的真实打开/读取该指派所产生可信opened_at，才结束其Console未读待办；身份不匹配、他人代看、预取、投递ACK不算。打开不代表完成审阅，具体可信回执接线仍待实现。扫描后打开与发送竞争在外发提交边界重核，打开提交后不再提交新外发；已交外部通道的在途消息不能承诺撤回，保留真实先后/unknown并停止新发。本轮外接渠道仅既有飞书personal私聊；群通知挂起，不依赖Slack/企微/Google或其它新集成。

### R6与R9同事件去重边界（R6-005）

R6负责坐标派审未打开，打开即停该提醒，30分钟首催/最多3次/至少1小时间隔。R9负责PM决策未明确回应，打开不等于答复；其候选24小时/6小时仍是R9独立待PM口径，不得覆盖R6已定规则。R9提案固定0b707acad08ebcf8c05ec0172c14b7f276f94794仅作边界依据，本单不改该冻结内容。

同一平台事件必须只有一种语义所有者（坐标派审或PM决策）；同事件/收件人/版本不能同时进入R6与R9调度。统一outbox按事件身份/代际/收件人/渠道/槽去重，禁止同一次事件被两套调度双重催办。Console聚合展示不复制事件；确有两项独立业务须各有独立事件/类型，不能仅同仓/commit就合并、互相消耗次数。R9不得套R6打开即结束决策，R6也不得因无PM回应无限外发。此处约束将来接线，不提前实现R9或裁定其提醒周期。

## T-03 反例与后续验证样本（未执行）

- 独立获权主体可读指定C；反格Agent无映射/撤read、只有服务账号有权、main没有openspec均失败关闭、无正文旁路；撤逐主体/固定SHA检查须在泄露或混读断言红。
- C2仅改勾选/交接节/纯archive移动不误报实质；夹带任务/需求/场景内容则标旧版本。撤比较保护应红，结论保留原SHA。
- 虚拟钟30/90/150分钟合法各一私聊；29分59秒、第四次、不足一小时间隔、打开后旧任务重试不得发。撤打开/上限/间隔保护分别红在对应断言，恢复后绿。
- 同一事件同时进入R6/R9只准语义所有者调度；独立两事件各自按停止条件处理。撤事件所有者/统一去重必须红于双催断言；打开PM请求不能冒充明确答复。产品场景和变异本单均未执行。

## Open Questions

PM执行口径按本次派单已定回写，原始rulings出处标“本席转述，待核”。R5 GitHub事实/实现已核，但可信Agent/Console映射、工蜂只读账号/API、真实打开回执、私聊收发/对账及持久调度仍待核验/实现。T-03勾选仅表示回写完成，不表示前置全部满足或授予实现/上线权限。
