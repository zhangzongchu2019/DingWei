## 1. 结构与边界

- [ ] **ARCH-01 🔴 边界、命名和抽象层成立。**
  - 证据：三件定位节、权威定义、术语表、架构图、设计约束表。
  - PASS：业务/技术/部署/数据库四面均覆盖；同名同义、异名异义；抽象层足以指导实现且不承载真实 secret/IP/代理细节；设计约束与具体设计分层。
  - FAIL：平行权威定义、同名不同义、关键架构面缺失、照此实现会写错，或把具体设计塞进 spec。
  - E.4：#11、#42、#62。
- [ ] **ARCH-02 🔴 全集断言、依赖闭包与跨件语义一致。**
  - 证据：依赖图、SYNC impact、typed 引用报告、正反向映射、全文 diff。
  - PASS：“所有/唯一/完整/零遗漏”有全集证据；引用不仅存在且引对义；复述点与依赖点全部同步。
  - FAIL：子集外推全集、引对号引错义、枚举互撞、历史句仍作为现行断言、近重复漏改。
  - E.4：#49、#58、#60。
- [ ] **ARCH-03 变更影响面与原型冲突有唯一裁断。**
  - 证据：SYNC impact、原型↔SpecDoc 映射、裁定记录。
  - PASS：影响面覆盖正文、附录、原型、脚本、交付状态；冲突只保留一个权威结论。
  - FAIL：两边并存，或仅改原句未改依赖消费者。
  - E.4：#27、#33。
- [ ] **ARCH-04 部署与交付物锚完整。**
  - 证据：现状/目标部署图、部署单元清单、环境/探活/回滚/故障边界、锚登记。
  - PASS：所有组件和故障边界均有 owner、状态及锚；运行态细节不固化进公开抽象层。
  - FAIL：漏组件、漏紧急旁路、锚不能反映目标变化，或把状态性事实写成长期规范。
  - E.4：#28。
- [ ] **ARCH-05 🔴 派发重灌与失败复现成立。**

  - FAIL：字段齐但信息不足、引用不可取、digest 不匹配或只能靠原 worker 解释。

- [ ] **ARCH-06 知识固化与替代锚判型正确。**

  - FAIL：运行态被固化，或替代锚不能反映原源变化。

## 2. 产品定义、分级与门

- [ ] **FLOW-01 分级可重复、无打分平均化。**
  - 证据：属性表、DMN rule IDs/version、两个独立填写样例、预计数据依据及复核点。
  - PASS：同输入可复算；安全面独立；基础必过模板最小且有理由；容量依据可验证。
  - FAIL：十档打分、主观总分、安全风险被平均、预计数据无可比依据。
  - E.4：#1、#2、#23、#61。
- [ ] **FLOW-02 🔴 gate 合取与专业独立性成立。**
  - 证据：gate key、责任域、multi-sign、subsumption 表、不可比较反例。
  - PASS：跨责任域评审并存；仅预定义 subsumption 可覆盖；不可比较时 fail-closed。
  - FAIL：用“更高权限”替代专业责任域，或滥用“无法比较”逃避裁定。
  - E.4：#12、#21、#32。
- [ ] **FLOW-03 能力判型、晋升与装卸路径正确。**
  - 证据：skill/MCP 判型、候选→晋升、push/pull、卸载 capability effect、mandatory 判定。
  - PASS：平台级准入脱离项目仍完整；晋升判据不被当候选触发；卸载/紧急动作不扩大权限。
  - FAIL：横向扩散、以晋升判据筛候选、数据/模板旁路契约或 mandatory 无依据。
  - E.4：#4、#17、#22、#29、#30、#39、#44、#53。
- [ ] **FLOW-04 定义层回写与复盘有实质。**
  - 证据：分歧原帖、解封裁定、定义层 diff、复盘四段及去标识化检查。
  - PASS：回写真正解决分歧；复盘非空洞；去标识后不可指认具体人/事故。
  - FAIL：只改状态未改定义，或复盘形式齐全但无信息。
  - E.4：#3、#6、#7。
- [ ] **FLOW-05 摘要、台账与周报实质一致。**
  - 证据：cursor range、引用、台账事实、提示注入隔离、三视图聚合样例。
  - PASS：关键决策回原帖；摘要与截止时刻结构化事实一致；周报来自同一任务事实层。
  - FAIL：仅凭摘要决策、引用不足、提示注入可改变摘要器行为或周报脱离台账。
  - E.4：#10、#26、#35、#48。
- [ ] **FLOW-06 🔴 外部/高权限锚具有真实独立性。**
  - 证据：威胁模型、权限主体矩阵、manifest/high-water/hash chain、定期核验。
  - PASS：能改业务库者不能同时改外部锚；遗漏攻击与重排可检测；RPO 明确。
  - FAIL：digest 与数据同权限，或裸 root 无数量/high-water/前序 root。
  - E.4：#24、#34。

## 3. 安全、身份与授权

- [ ] **SEC-01 🔴 数据可见性与泄漏面逐层闭合。**
  - 证据：domain×visibility、运行态查询、附件定级、日志/错误/redaction、status 与时间窗组合分析。
  - PASS：装载前求交集；敏感内容不经错误/日志/offset/status 侧信道泄漏；基础设施 sink 也覆盖。
  - FAIL：只查应用层、先检索后过滤、可由摘要/长度/状态/时延反推敏感事实。
  - E.4：#5、#25、#45、#50、#56、#57、#59、#63。
- [ ] **SEC-02 🔴 预授权与跨租户能力最小且不降风险。**
  - 证据：policy 六项绑定、resource scope、批准主体、用途/有效期、风险分级与逐次审计。
  - PASS：无通配/整租户；批准者真有权；预授权只改路径不降低固有风险。
  - FAIL：角色名替代批准权、通用 read/export、白名单旁路 capability 或无限期授权。
  - E.4：#8、#14、#31、#36、#40。
- [ ] **SEC-03 环境属性可信。**
  - 证据：部署件声明、服务端取得、凭据策略消费、伪造环境负测。
  - PASS：调用方不能自报；缺失/不匹配按最严处理。
  - FAIL：环境属性来自请求或虽声明但未用于授权。
  - E.4：#9。
- [ ] **SEC-04 🔴 副作用与紧急路径不绕契约。**
  - 证据：capability effect、guarded primitive、幂等/CAS/审计/outbox、fail-closed fallback。
  - PASS：权限/外部副作用均由结构化 capability 承载；紧急只单调收紧；机制不承载其要防的 secret。
  - FAIL：模板、配置、allowlist、自由文本或“紧急”成为免审旁路。
  - E.4：#13、#16、#38、#47、#51、#54。
- [ ] **SEC-05 🔴 reviewer 与批次签署保持独立。**
  - 证据：责任域、批次项、风险档、两 principal 签名、拆批理由。
  - PASS：高危无漏认；互不相关项不捆绑稀释；执行者不作门方。
  - FAIL：自签、单签高危、为降签拆批或以大批次掩盖单项。
  - E.4：#15、#18、#37。
- [ ] **SEC-06 身份绑定所有权真实。**
  - 证据：IdP issuer/audience、双向 challenge、主锚、解绑审计。
  - PASS：新旧渠道分别确认且不可复用会话；弱因子不决定强身份。
  - FAIL：按邮箱/显示名自动合并，或新渠道自批绑定。
  - E.4：#46。
- [ ] **SEC-07 敏感内容判定器适合本域。**
  - 证据：词表/模式版本、域样本、误拒/漏拒、输入隔离。
  - PASS：覆盖本域真实形态且词表自身不泄密；判不准时取更高密级。
  - FAIL：只用通用词表、持久化原始匹配串或判定器不可用时放行。
  - E.4：#52。
- [ ] **SEC-08 🔴 deny 不泄漏资源存在性。**
  - 证据：状态码、响应体、时延分布、审计、查询执行顺序的负测。
  - PASS：deny 与 not-found 对外不可区分；拒绝先于查询并落审计。
  - FAIL：成功空集合、不同状态/文本/时延确认存在性，或先查后拒。
  - E.4：#64。
