# ⛔ checklist —— 未产出，且本席不得代写

> **本文件不是 checklist。** 它是一份「为什么这里还没有 checklist」的说明。

## 为什么本席不写

**checklist 是 reviewer-owned**（SpecDoc §4.1）：只有 reviewer 能打 `[x]`，
IMPLEMENT 读 checkbox 当门、且不得修改标记。这与 §7.2「implementer 不能自签门 PASS」是**同一条纪律**。

🔴 **本席是本 spec 的执笔方。执笔方自备 checklist 自己勾，等于自签门 PASS。**
§0.4 已明写：**本席不得代写**（§4.1、§7.2）。

⚠️ 附录 **E.4 第 IV 类（评审检查项）不是 checklist** ——
它是**作者提供的候选输入**，供门方取用或否决；门方照单全收也须是门方的决定，不是作者的授权。

## 谁来写、什么时候写

| 项 | 规定 | 锚 |
|---|---|---|
| 产出方 | **架构评审门方**（须含安全角色 —— 本 spec 安全面=是） | §5.8 · §4.1 |
| 时点 | 🔴 **架构评审【开始时】生成，作为评审的【输入】** —— 不得评审结束后补 | §0.4 |
| 持有 | 由门方生成并持有；只有 reviewer 能打 `[x]` | §4.1 |
| 效力 | **门方产出 checklist 即为本 spec 生效条件之一** | §0.4 |

## 当前阻塞了什么

**SpecDoc 生命周期＝草案** ⇒ 按 §0.4，**不得被任何子 spec 引用为依据**。
⇒ SP0–SP8 全部子 spec 的正式开工，卡在这一项上。

⚠️ **时点已经错过一次**：§0.4 要求 checklist 在架构评审**开始时**作为输入生成，
而 2026-08-24 的三域架构评审**已在无 checklist 的情况下完成并 PASS**。
⇒ 须由门方补判：**该轮评审是否因缺少规定的输入而须重走一次**，
本席不代门方判此事（判了即又一次自签）。
