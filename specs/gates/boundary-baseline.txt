# SP7a 仓储包边界基线 —— 每条判据【各记各的】，不合并成一个总数。
# 🔴 不合并的理由：合成一个和就允许「一个降一个升」而总数不变地过闸。
#
# open    —— 仓储包外直接建库调用（允许清单豁免）。口径为业主已裁的【严口径：含 _test.go】。
#            🔴 不设双值、不留 INCLUDE_TESTS 开关；include_tests/open_prod/open_all 三键回潮即判闸坏。

#            🔴 允许清单【不】豁免本条：仓储包自己导出 DB() 正是「句柄出了仓储包」本身。
# pending —— 尚未租户化的调用点（dtx/ftx/PendingTenantCtx）。**SP7b 的显式债**，只许还不许添，终值 0。
# system  —— 显式 SystemCtx 调用点。每一处都是评审面（「这个操作真的与租户无关吗」），不许悄悄增长。
