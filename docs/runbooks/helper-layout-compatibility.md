# MCP 首升布局、兼容边界与后续建议

依据组长 2026-10-16T02:47:01Z 裁定。本轮只实现新首升布局的稳定 MCP 转发器；以下目录区分及前向兼容为文档建议，不冒充已上线功能。不实现 S-LAYOUT-MIGRATE，不改旧校验器，不迁移任何 Agent。

## 两条交付线

| 用途 | 源码/布局 | MCP | 当前允许范围 |
|---|---|---|---|
| 已首升的 oaagent 后续升级 | r15 `review/coder/helper-0232@b5faf73c8fe4d5c71720daf4eed5b133b8d45dbd`，tree `430e29b31fdd4b334f69f6ad21efb8171ff94006`；旧布局0.2.3.2 | factory 脚本路径，重启对应 Codex后验收九工具；自升级不改变 factory 版本 | 继续原定 oaagent 单席 Console 0.2.3.2 验收；仍需原执行授权/窗口 |
| 今后手动首升 | `review/coder/mcp-forwarder` 精确经审提交；新布局0.2.3.2 | 根 `sessionhelper/mcp_shim.py` 转发器，module形态随已确认 current，缺失/无效时 factory | 未首升的原布局，经逐席 preflight 与授权后手动安装；本轮只交候选 |

两线可以有相同显示版本，但包成员和 SHA 不同。不能只按版本0.2.3.2选择制品。旧布局到新布局包会被旧白名单以 `manifest_invalid` 拒绝，拒绝是停止条件，不是安装成功。新布局校验器保留接受旧格式包的能力，但若接受旧布局制品作为后续槽位，选中的 MCP 仍来自该槽位；不能据包名推断功能或版本。

oaagent 当前最小恢复为保留已认可的 factory 脚本 MCP 配置，由负责人在获准中断窗口重启 Codex或开新会话，再做 initialize/tools/list 与真实 Codex 九工具可见验收。此操作不补根转发器，不创建/改 journal，不迁移布局。factory脚本在升级前后都应能列九工具，版本仍为 factory 的0.2.3.1；活动 helper升级到0.2.3.2的证明来自真实认证连接及作业confirmed，不能用factory shim自报版本代替。

新首升执行单 `oaagent-helper-bootstrap-mcp.md` 与通用版 `helper-bootstrap-generic.md`（后一件在 P2 分支）面向新布局，不替代 oaagent 现行旧布局包的已审执行记录。新布局手动首升0.2.3.2以后，再做真正自升级需要另一个经审且高于0.2.3.2的版本；本轮不伪造新版本或放宽 version_not_new。

## Console/目录的最小区分办法（本轮不实现）

当前不能假称 Console 已能按布局过滤。最低限度是在制品外部经审发布记录中绑定 `commit/tree + sha256 + version + layout`，将用途明确标为 `legacy-upgrade` 与 `stable-mcp-bootstrap`。每次由执行人在 Console 按精确 SHA 核对，仅选择明确属于该席布局的制品；显示名或版本相同不能替代 SHA 核对。新首升包不登记进目前向旧布局席位下发的可选列表；原旧布局0.2.3.2登记及oaagent验收保持原坐标。本轮未登记目录、创建作业或改 Console。

如果现有目录只能提供一个无布局区分的版本条目，则先只保留旧布局可升级条目，新布局包由受控手动首升交付；不能将两包混为一个版本记录。长期建议制品登记增加可信 `layout_id`/`requires_launcher_format`，Agent认证连接声明对应能力，Console服务端在 offer前核对、过滤并拒绝错配。仅在前端改名不足以成为强制门。现有MANIFEST format=1没有这些已定义语义；本轮不私加字段冒充支持。

## 声明可选根成员的前向兼容评估（本轮不实现）

现状：MANIFEST format=1含每个成员的bytes/SHA，验证器还做硬编码根成员白名单。新增根文件即使有正确pin也会被旧校验器拒绝。稳定校验器不会随槽位自升级，因此仅修改新包不能让旧安装接受新成员；格式字段也无法追溯改变旧校验器。

建议未来定义经审核的 format=2 合同：由稳定校验器预先认可有限的可选根成员集合及用途，再要求 MANIFEST显式声明所用可选成员。接受条件必须同时包括：支持的format、声明名称处于该有限集合、声明与实际成员完全一致、所有bytes/SHA符合、普通文件/路径无越界/无重复、大小和secret/private-state扫描通过。MANIFEST是待验包自己的声明，不能让它自行授予任意路径权限；“只要声明就接受任意根文件”不成立。format版本未知、声明未知成员或漏声明都必须拒绝。

可选成员仅能扩展允许的包结构，不意味着自升级可写稳定根。当前updater只提取factory内容到私有槽位；稳定根的新增/替换仍须专门授权、备份和回退合同。长远可将稳定转发职责限制为固定入口，扩展功能放槽位，以降低根成员变化频率。旧席进入新合同属于另立的 S-LAYOUT-MIGRATE，暂不开工。

后续若获准实现，最少负格应包括：未知format、未知/越界/重复根名、未声明成员、声明缺实物、pin/大小错误、软链与特殊文件、secret/env/private-state、声明可选但试图覆盖稳定根，以及旧format回归。还需新旧布局与真实自升级/回滚矩阵，不能只测新验证器验证自己生成的包。当前变更保持format=1，只为本次明确的MCP根转发器增加固定白名单。
