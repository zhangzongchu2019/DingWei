# helper 下发与旧公开制品入口退役

2026-10-15：本页记录新的安全边界和旧入口退役，不提供未发布制品的下载命令，不代表部署或升级授权。自升级核心、Console 界面与真实 Linux 容器矩阵须组合审核通过。

- 旧匿名 `/dl`、`/dl/` 和其下文件一律 404，即使历史文件仍在磁盘。Hub 不删除旧文件；由运维统一私有留存和下线。`WP_PROVISION_DL_DIR` 不再生效。
- 旧后台公开上传和 `package_self` 在线打包返回 HTTP410、`error=public_upload_retired`。在解析 multipart 请求体前拒绝，不生成临时上传文件、制品或匿名链接。页面不再提供上传或打包控件。
- 已有 `install_skill` / `install_mcp` 制品 URL 下发仍使用原权限、主机校验、可信来源与 ACK 流程；不因此获得新的上传授权。通用 skill/MCP 源码交换仍走 Git。
- helper 升级只能选择由运维在 Hub 主机 CLI 登记的目录项，Console 不接受自填 URL 或 SHA。成功以核心校验过的重连版本与关联健康确认展示，不能把“已下发”或“已安装”写成“已上线”。

首次手动引导可从批准的文件服务 helper 包＋独立 SHA256 获取（默认），或从精确 Git commit 获取。必须使用审核后的清单、白名单打包和 bootstrap 步骤：下载、核 SHA、检查锁/入口/持久状态、仅在本机备份、替换、重启、核版本和 IPC/消息/A6。旧 helper 下载器不能承担首次升级。具体 URL、commit、SHA、容器与状态目录由发布单和执行人的 preflight 填实；当前没有可照抄的已发布制品命令。

源码升级包和说明适用业主明确例外，但包内禁止 key、凭据、env、inbox、ledger、日志及私有状态。凭据保留在原私有位置，不随下载提供。Linux 容器是首版自动升级范围；macOS 只做手动升级。

历史资料盘点：`docs/v0.1/自助申请key-spec.md` 的匿名 curl 已替换；旧 provision 通道/发送方规格标明退役；旧发送方测试计划与报告保留历史事实并加醒目退役说明。没有把历史通过记录改写为新证据，也未探测任何历史外部链接。已知外部接入包调用方仍须由发布负责人核对并迁移，不能声称全仓检索证明没有外部使用者。
