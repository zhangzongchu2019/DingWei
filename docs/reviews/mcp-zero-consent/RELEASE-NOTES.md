# 默认授权发布注意事项（不含发布授权）

依据㊿-补29；本分支只实现与隔离验证，不修改现网配置、不部署。合入版本由组长决定，不并入r57子Agent线。

## 配置与权限

新增可选 `DW_MCP_CONSENT_TARGETS_JSON`，内容为 JSON 对象，例如 `{"example-tenant":["Helper.owner"]}`。key为可信飞书租户，value为普通Agent全名的允许数组，每租户最多64个、拒重复/非法全名。缺席、空对象或本租户空集合均默认关闭，保持原短名（1～8）与目标两项手填，不从在线清单猜目标。现网初始集合须组长另定并经业主确认，本分支不提供任何真实初始值。

恰一个配置目标现核有效时，无可编辑输入，点击同意并进入飞书即可。配置多个时，先飞书验证取得可信主体，再显示一次受控单选：仅列现核有效的允许目标，并预选该主体最近一次成功签发且仍有效的目标。不认识主体时不猜最近目标；无历史则不预选。所有目标失效时拒绝，不能回落任意Agent。选择票据与原OAuth attempt、浏览器cookie绑定，一次性且有原期限；目标在签发前再核，原extseat/AG事务还会锁定目标与属主状态。

只创建原来的双成员临时AG，保持四项通讯scope，不加入全组织，不授予宿主执行权。撤销配置只在新进程配置中生效；没有在线修改接口。

## 长名兼容与回退硬前提

新增 `0108_extseat_short_name.sql` 放宽 `np_extseat.short_name` CHECK为1～20；不改0105/0107等已发布迁移。旧1～8位行原样有效，普通Agent 2～32、用户简称2～16不变。手填入口仍限8，自动名字部分最多8＋UTC十二位时间；AG序号不复用，同秒同名依靠AG区分，主体按稳定四元组区分。

关闭默认授权功能只停止产生新的长名，不改已有长名，不截短、不重命名、不删除投递与ACK。

回退到不认长名的旧二进制之前，必须：

1. 封口全部长名外部席位，拒绝新受理与新投递。
2. 处理完这些席位确定未执行的投递，未知状态单列核证，保留墓碑与ACK，不将未知伪作未执行。
3. 核验旧二进制不再接触任何长名席位或相关投递；未完成前禁止降级。
4. 存在长名行时不得恢复旧CHECK，只能前向修复。关配置不是完成回退验证。

发布单专项验证必须包含：迁移前后旧行逐字比对、20位可写/21位与非法字符拒绝、关闭后长名原样可读、存在长名时恢复旧CHECK失败并保留新约束、全部长名席位封口及待投递分类/墓碑/ACK证据。缺少其中任一项不得据本单宣称可回旧二进制。
