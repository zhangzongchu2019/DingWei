## Implemented interfaces and boundaries

- Human Console: current PM/deputy policy; typed append and bounded thread reads; actor-scoped request status; revision-pinned public spec posts without private D3 history. Agent HTTP/MCP only reads and non-authoritative anchored technical posts. Old untyped substantive/input writes are refused with 426, including direct store calls; a missing PM never falls back to owner/editor/responsible/leader authority.
- Owner D3 recipient configuration updates the same current PM policy and append-only history atomically. Replacing PM clears the deputy. Existing owner-selected PMs are backfilled without relabelling old answers. New questions require validated immutable entry references. Old answers retain historical/unverified labels and stay behind their existing ACL.
- Native authenticated SDK ingress preserves app/tenant/parent/sender/message/event metadata before redaction and durable enqueue. Event/message key conflicts are checked before generic message dedup. Exact notice parent is the only positive match. Early replies are durable and reconciled; no guessed mapping or provider resend. Distinct same-parent messages append supplements, even with equal text. Recognized invalid replies are not Agent instructions.
- `DW_SPEC_CLARIFICATION_FEISHU_TENANTS_JSON` pins non-secret issuer-to-tenant authority at startup. Application IDs come from native gateway configuration; bindings are re-read under PG locks. Unverified FCS/webhook/fake paths cannot mint reply authority. Missing capabilities/configuration remain pending_config. Receipt sending is independent of the D3 outbound switch.
- Mobile thread: 390/820 layout, minimum 44px controls, explicit posted/unknown receipts, persistent same-ID retry/status lookup, no HTML rendering of posts, and single-use cookie-bound login continuation after ordinary human login. In-app browser fallback is explained; actual Feishu in-app acceptance remains a rollout-window check, not a local viewport claim.
- Mobile attachments: private file-service-only image storage, never public object paths/permanent links. Hub checks current question ACL for upload/read, bounded actual image type/size, max four images per post, successful-upload ownership, immutable metadata/links and content SHA on retrieval. Unfinished/failed uploads cannot attach. Private image storage has a separate 1 GiB fail-closed ceiling and no automatic evidence deletion. File-service binary upgrade is needed for this endpoint; an old service yields explicit failure without public-link fallback.
- Task/spec/project_context projections contain only new thread data. Context projection is limited to the currently assigned task's exact revision/SHA; a new floor changes the cursor fingerprint even after task completion. Corrections enqueue non-executable task-flow notifications without reopening completed work. Existing D2 limits and scope-change gates remain in force.
- Helper/MCP/root/Go version pins are `0.2.3.8`; runtime dependency lock is unchanged. New tool: `dw_spec_clarifications` (list/technical/status). No PM impersonation/finalize/authority fields are exposed.
