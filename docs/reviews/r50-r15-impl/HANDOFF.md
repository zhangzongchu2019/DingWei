# R50 R15 session history implementation handoff

Status: implementation handoff for independent pre-review; this is not an acceptance claim.

## Scope and current tip

Branch: `review/togpt60lunazzc/r50-r15-impl`

Tip: `4b8b6f81d` (`Keep Hub available when disabled history store fails`). Prior implementation and View changes are in commits `804dbcb3` and `9f969b77e`.

The feature switch is `DW_SESSION_HISTORY_PERSIST_ENABLED`; only the exact value `1` enables persistence. Startup attempts to open and migrate the independent history store in either mode. When the switch is off and this open/migration fails, startup logs one warning with the path and cause and proceeds with a nil store, disabled API (503), and r49 event behavior. When the switch is on, the same failure aborts startup with the database path in the error. The independent history migration remains isolated from the primary database and version metadata.

On a writable data directory, the first off-mode startup creates and migrates `workpulse-history.db`, then writes the disabled state to its runtime table. While open in WAL mode, SQLite also creates sibling `workpulse-history.db-wal` and `workpulse-history.db-shm` files; these are runtime sidecars and can disappear after close/checkpoint. The files are owned by the WorkPulse service account (`User` generated by `deploy/install.sh` from `id -un`) and that account's primary group; the unit has no `Group=` override. SQLite creates files with mode 0644 masked by the process umask. The current systemd unit template does not pin `UMask`; under the normal system-service default 0022, the resulting mode is 0644. The actual service umask remains host runtime state and should be checked on the target before snapshotting.

Rolling back to r49 leaves these files untouched. r49 does not open or read `workpulse-history.db`; the database and any sidecars may be retained. The off-mode runtime table contains no history events because event persistence remains guarded by the feature switch.

## Disabled-mode equivalence criteria

With the switch off:

1. SSE bodies contain neither `_history` nor `_history_gap`.
2. A clean writable data directory may receive the migrated database and WAL sidecars, but no history event rows are written. An unavailable or unwriteable history path does not prevent off-mode startup.
3. The View does not show the “向上翻页” button after the history endpoint returns 503. The button's `hidden` state is enforced in CSS despite the shared `.text-btn` display rule.

The Go regression tests assert off-mode no-write and failure handling. The Chromium regression checks the visible button state. Mutations removing the persistence guard and CSS hidden rule failed their corresponding tests.

## History request failures and live stream

The View silently ignores a non-2xx history response and always clears `historyBootstrapPending` in `finally`, then drains queued live SSE events. The regression exercised 503, 401, 404, and 500. For 503, the mocked disabled-mode SSE event has no history metadata and the button remains hidden. For 401/404/500, a live event carrying a history cursor is still rendered; a pagination control may be surfaced by that cursor even though the history fetch itself failed. Removing the bootstrap reset was killed by the browser regression.
