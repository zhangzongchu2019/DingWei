S-D2-WAKE-HELPER-FAILED — candidate review evidence

Problem and resulting behavior
Production Credential is a frozen dataclass with agent_name and secret only.
Both the durable delivery worker and the driver dispatch preflight read a nonexistent agent_id; the former records failed and the latter cannot admit the wake.
Hub now returns X-DW-Agent-ID from the already authenticated identity Agent on a successful dedicated WebSocket handshake. The helper binds only this response header for that connection. The request URL, envelope metadata/body and Credential display name do not supply identity. Reconnect start, producer exit and worker-connection cleanup clear the binding.
Both wake paths use the bound identity while retaining the authenticated current blocker read and assignment/generation/input/state/full-approval checks.
Absent or malformed handshake identity explicitly logs current_agent_identity_unavailable and notice-only downgrade; the durable worker emits processed with that reason without injecting a model turn, and driver preflight refuses admission. This is an explicit notification-only fallback, not proof of CLI injection. Old Hubs without the response header take this fallback: full automatic D2 requires the Hub and helper changes together in a separately authorized future release.
