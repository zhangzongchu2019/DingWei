# S-PGTEST-PARALLEL-ZOMBIE

基 integration/spec5ff-r31＝4fbcf26e，独立分支。先归属，再修独立残留核对的确定性错误；不改工具收尸逻辑、不关闭守卫、不杀或清理任何外部进程。

## 归属证据与限制

在本轮真实全仓并行期间，只读观察 /proc，按 PID＋start_ticks 连起 live 与 Z，记录 PPID、pgtest子收割器、所属测试包、postmaster命令中的 -D 数据目录及UTC；随后核这些PID已消失。OWNER-TRACE.jsonl 是有界原始成对摘录，SUMMARY记录所属包。本轮的多包postmaster会进入短暂Z，随后由各自仍存活的pgtest回收，不是证实的PID1永久孤儿。正常短暂僵尸出现本身不能证明收尸故障。

历史组长那次identity失败未提供当时PID/proc快照，不能追溯究竟是哪一个包/进程，不冒称已坐实它就是本轮缺陷。修复结论限于下述可重复的守卫误判；其他收尸问题若出现需以新现场另判。

## 已证明的判据缺陷与修复

旧check只要求第一轮新增集合非空，等250ms后第二轮新增集合仍非空；不要求为同一PID。并行包中的A已被正常Wait、B正好退出，就会被误说成A持续未收。这个错误无需库本身收尸失败即可成立。

改为只报两轮集合交集中、起库前未有的PID。持续新增僵尸仍为红，不按“属于其他包”豁免，不去掉全局增量守卫；两轮之间已回收的A和后出现的B不会互相冒充。文案明确为同一批新增PID两次均见，历史成因改为可能成因，避免凭单条进程计数断定PID1孤儿。

纯集合格覆盖轮换、真实持续新增、历史排除和混合交集。真实/proc反例依次启动两个本测试拥有的comm=postgres短命子进程：A留作僵尸两读必须可检测；Wait A后启动B，两轮独立新增均非空但不能判为同一残留；始终Wait自有孩子，不制造PID1孤儿。实际check端到端格在子测试进程注入确定性两轮读数：轮换应成功，持续同PID应由t.Errorf失败。撤回交集时 ROTATING_GUARD_FALSE_POSITIVE 必红；关闭持续门时 PERSISTENT_GUARD_DISABLED 必红。不是只测一个未接线的helper。

PID判据沿用现有以PID标识进程的增量接口；未新增对极端250ms内PID复用的保证。本件不宣称改了PostgreSQL进程生命周期或修了所有潜在收尸缺陷。

全仓Go读数交件时追加；完整独立审查归togpt60，不部署。
