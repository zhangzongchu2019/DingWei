## 权限、事务、兼容边界

- **身份与同组**：人类写路由沿用 Console cookie、同源校验，拒 Agent bearer 混用；Agent 新路由只接受专用 Agent bearer，复核 Agent 与所有者 active，不接受 cookie、共享 key、5分钟人签 capability 或 body 自报身份。MCP 经新增 `task_flow_v1` 本地 IPC 到 helper，再请求已配置 Hub；凭据不进 shim／日志，禁止任意目标 URL。写需 request_id＋expected_version；同 ID 同载荷返回既有结果，不同载荷409；超时回 outcome_unknown，先查询、不盲重试。
- **组与归属口径（组长裁定1／2）**：以新平台 identity 的组码／active 成员为准，非“同属一个用户”。可选 spec 所有者参与的组（自己创建或拥有 active 成员），开发／审查须为该组不同的 active Agent，同 owner 的两个不同 Agent 可分别开发／审查（组长最终裁定）。关闭添加不撤成员资格。建议、确认、改派均从真实 identity 解析 Agent，不比较展示名或客户端自报身份；确认／改派时存真实稳定 Agent ID、group_code、assignment_version；双方 owner_principal 从受锁 identity 主数据解析，不信任客户端自报归属；每次读写重新校 active 身份与当前组成员，退组、移组、吊销或停用立即撤回该任务读写权，不能靠旧指派继续访问。离线不撤权。投影按 identity ID 同步，不靠全名猜旧记录。失效任务派生 needs_reassignment=true，禁止继续执行；身份变更后的持久补登及所有者通知用幂等 outbox 重试，读写发现失效也触发补登，不等待补登才拒绝。单纯 PG 故障只拒请求，不误标已退组。
- **两库顺序与失败（组长裁定3）**：SQLite 为任务状态提交点，不做跨库两阶段提交。①每请求在 PG 普通读写授权事务中（不写业务数据，FOR SHARE 不可用 SQL READ ONLY）重核 Agent、所有者、被指派组当前成员，必要行用共享锁；确认／改派另核所有者可指派范围。②授权成立才开 SQLite 写事务，复核任务当前执行人、group_code、version及状态／依赖／用例门；写任务、幂等结果、审计、outbox。③提交前在仍持锁的 PG 事务重核身份／成员，失败或连接丢失则回滚 SQLite、拒写；成功才提交 SQLite，随后释放 PG 授权事务。实现锁序为组→排序后的 Agent→排序后的 active 用户；退组／删组与组锁串行，停用与对应 Agent／用户锁串行：撤权先完成则拒；本次任务先完成则可提交，撤权完成后的新读写必拒。读请求同样 PG 授权后读 SQLite 并复核版本，释放锁前形成受权 DTO。SQLite 失败全部回滚；提交回执不明返回 outcome_unknown，按 request_id 查询，绝不假称回滚或自动重发。PG 释放失败发生在 SQLite 已提交后也不得声称任务未写入。人类旧任务／看板入口共用状态门，不旁路 done。
- **通知与旧 helper（组长裁定4）**：任务事件仍为 meta.kind=task_assigned，稳定 ID 经既有可靠 delivery；通知由内部 outbox 发出，普通 Agent 不可伪造。新增 task_flow_v1 能力协商；新 helper 将该通知识别为通知而非执行指令，禁止自动回信／自行更新任务。对未声明能力的旧 helper，不把未知 kind 包装成普通用户正文注入 CLI；业务通知留在 Hub outbox 等升级，Console 明示等待升级，可沿既有安全升级提示通道提醒。不能以 no_reply 代替禁止执行；不伪造 processed ACK、不把提示当投递成功。测试精确 r31.1 helper 无 adapter.handle／pending_inbound／CLI 注入，无自动回信；升级后排队通知去重送达，原 delivery ACK 状态机不改。
- **版本与 driver inbox**：拟统一发布 `VERSION`、helper `__version__`、MCP serverInfo 为 **0.2.3.5**，构建前再核版本占用；旧 Hub 对新工具明确不支持，旧 helper 无新工具时提示升级，不静默降权。此批一并修 driver `dw_inbox` 的 desktop_inbox_unavailable：status／list／read 查询本席 DeliveryInbox，ack 只记本地独立“已读”标记，不回写 Hub；不改 accepted_to_cli、重试、取消或 Hub processed ACK。driver 的 pause／resume／wait／reply 返回明确 mode_operation_unsupported，不伪装桌面暂停／已回复；desktop 现行为保持。分页、跨席隔离、重启已读保留与读取不吞自动投递均测。

## 迁移、回退与交件门

spec／任务目前属于 `internal/store` **SQLite schema_migrations**（文件名＋digest），不是 hosted／identity 的 PG 账本。拟新增 `0055_console_task_flow_r32.sql`（presplit 候选、任务版本／指派代次、请求幂等、审计／通知 outbox）及 `0056_console_spec_agent_review_r32.sql`（review／criteria 请求与候选）；优先新增旁表，必须加旧表列时给默认值，不修改0054及更早迁移。helper 本地 inbox 另走现有 `_migrate_schema`，新增已读旁表；不改 delivery 状态 CHECK。实现前核编号冲突。空库、精确 r31.1 旧库带任务升级、重复迁移／重启、失败回滚均须实测；旧二进制的实际启动和任务／spec 读取单独验证，不能仅凭 additive 宣称通过。

旧二进制可读不等于保留确认门／指派授权／预审锁：降级前必须关闭 R32 的人／Agent 写入口和任务驱动，取消或完成 pending review／criteria／presplit 请求，冻结 outbox；恢复旧版只能受控只读，需可写则交保留这些门的兼容回退版。不删新表或回写账本；通知须保留去重标识，不以降级重新发送。r31.1 部署线不由本设计改变。
