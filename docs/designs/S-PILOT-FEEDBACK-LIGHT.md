# D3 轻量档 · 飞书集中答一次，回到原任务（一页，待审）

**试点默认路径；完整档按需附加。** 本页按组长轻量意见追加，原 [D3 完整稿](S-PILOT-FEEDBACK.md)保留。基 r32.1 36afa621；仅设计，不向产品经理/飞书发消息，不表示卡片/回调现已实现。

**PM 只做三步**

1. **定期打开飞书待答清单。** 每条显示原 spec/任务、问题、所等答复和等待时长；类型只选四种：需求不清、变更、技术受阻、缺资源。执行者从原任务发起，系统带上下文；PM 不另建台账。
2. **集中答复，必要时转派。** 业务问题直接答；技术事实/资源问题交有权负责者，不要求 PM 猜技术结论。可用安全的已绑定飞书回复；若尚无可靠回调，则从清单链接登录平台集中答，不能从任意群聊天猜答案。联系人身份未绑定就明确待配置，不按姓名猜收件人。
3. **看回写和后续。** 答复自动追加到原任务的问题记录，复用 D2 通知并唤醒执行者一次重核；显示材料仍缺/已恢复。业务需求改变时显示变更提案供确认，不能悄悄改已认领 spec 或把答复当签收。

**默认只保留必要信息。** 问题挂 spec/任务；写问题类型、事实与期待答复，系统带版本/发起人和责任人。未关联任务的仍是 spec 问题，后续由 owner 确认关联，不自动派任务。陈玉玲定期看飞书无需全天在线；所有人只看到自己获准问题的必要摘要，不默认获得全组/spec 权限。

**一小时规则。** 从服务端登记问题起记时；首份有效身份的实质答复计首答，“收到”不算。超过 60 分钟未实质答复，提醒项目配置组长一次，不循环轰炸 PM；重复投递/编辑标题不重置计时。离线照样计时，答复与提醒同时发生按实际先后记录。没有绑定/通知失败要显式显示，不能假称对方已收到。答复到件、任务恢复、最终签收各记各的结果。

**复用 D2，单人可走。** 不另造唤醒机制；重复答案不重复记、不重复唤醒，无新输入不重复报阻塞。单人团队可自问后补材料，但保留原问题/新输入/重核过程；需独立复核可用审查 Agent。Agent 能提交技术材料，不能冒充人类 PM 的业务决定或最终签收。旧 helper 只安全提示待升级，不把答复正文当指令执行。

**完整档何时附加。** 跨团队分级、正式审计/复杂分派可由 owner/受委托组长选择原完整档；真实生产动作或安全面自动升完整档，补具体授权与对应门。风险解除后降档须 owner 确认新版本，不能靠改问题类型降级。身份校验、权限隔离、去重和保留原答复仍是轻量底线，自动处理，不让 PM 填技术字段。

**不能降低：** 不伪造证据/送达/答复；unknown 不算完成；未授权不做真实动作。真实签收仍由已接受责任的人确认，业务变更不覆盖旧版本；超时提醒不是授权。轻量验收看 PM 三步、自动回写＋D2 一次重核、一次 60 分钟提醒、越权/重复拒绝即可。本页不创建对象、不发送外部消息、不实施上线。
