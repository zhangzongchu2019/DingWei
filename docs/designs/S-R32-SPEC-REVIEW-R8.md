| W8.1 / A23、A24 | 当前有编辑权的人类所有者（含合法 transfer 接收人）选择本人可用的在线 active Agent，`POST /api/console/specs/{id}/agent-review` 携 `agent_id,expected_revision,client_request_id`。Hub 发 `console_spec_review_request`，含固定 spec 修订、SHA、正文、acceptance、请求与截止时间。发起事务校非 final/非 archived，并将当前修订置 review（保留编辑人）；Agent 回 `console_spec_review_result`；单事务写该修订 gate review，来源 Agent 由认证上下文取，issues 只含唯一 id/text，服务器全部设 `outcome=pending,response=""`，不接受 Agent 自报人类结论。页面轮询显示，当前人类逐条标 true_problem/false_positive 并填写 response，人工保存后才可 finalize；空问题清单也须人显式确认。 | 真回信可见且来源正确；Agent bearer/WS 不能人工 review/finalize。撤来源绑定、pending 强制、人工确认各命中指定红；人工不得替换 Agent 身份、问题 id/text 或凭新增问题覆盖原回信。 |

**身份、范围和重放。** 选择范围沿用现有 presplit 的 owned-Agent 列表与 active owner 身份投影，本批不扩大为任意在线跨用户 Agent；transfer 后由新编辑人选其可用 Agent。请求行绑定不可变 `request_id`（随机128位以上）、kind、spec_id、revision/SHA、发起人 principal、Agent ID、认证 endpoint、generation、created_at/deadline、Hub boot generation。WS 回包从实际 sessionClient 解析 Agent；MCP HTTP 从 dedicated Agent bearer 解析，拒 cookie/混合认证；都调用同一接收器，禁止信任 Body/From/Meta 自报身份，拒不存在/停用/换身份端点。请求快照最多1MiB，回包最多128KiB、issues最多100条、criteria最多100条且每条cases最多100项，拒超限不截断；关联字段全部匹配且 pending 才能消费；同 Agent 同 payload 摘要的重发返回原结果，不再写 gate/revision，异 payload 或已取消/超时/旧代次返回409，其他 Agent 403。人类接口不因 request_id 获得额外权力。列表/获取请求只向该请求当前认证 Agent 返回，状态读取失败关闭，先选后读及 PG 锁内再次检查 Agent、状态、编辑人、revision，补改派/transfer 竞态格。

**超时和投递。** 等回包180秒（含投递），criteria 回包后的人工确认15分钟；使用服务端 UTC，测试注入时钟。发送前要求在线且已协商 `spec_review_v1`，离线409 `agent_offline`，旧 helper409 `helper_upgrade_required`，发送失败502并终止；请求发出后掉线不无限排队，180秒到期明确 `timed_out`。GET/所有写入均先在事务内惰性到期，另周期扫尾；Hub 重启把旧 boot 的 pending/awaiting_confirmation 明确置 failed，释放锁，迟到回包拒。请求创建与待发 outbox 同事务，发送器仅在deadline内重取已绑定且仍协商能力的在线会话；绝不向未协商的新连接补送；gate/候选写入与请求终态、审计同 SQLite 事务；掉回复可按同 client_request_id 查原结果，不自动新建。终态原因在页面可见；可靠投递 ACK 只代表收到，不代表业务完成，不延长期限。重复投递只处理一次。

**helper / MCP 通道。** 新增 `dw_spec_review_requests`（本人请求的有界列表/按id获取）和 `dw_spec_review_reply`（kind+request_id+revision+结构化 issues 或 criteria/cases）；MCP→本机 IPC→固定 Hub HTTP `GET /api/agent/console/spec-review-requests`、`POST /api/agent/console/spec-review-requests/{id}/result`，15秒 HTTP 超时，不重定向、不接受目标URL/凭据参数，不把 bearer 交给 CLI。helper 只在完整版本具备此通道时宣告 spec_review_v1；Hub 只有向该能力会话下发两个新请求类型，不把它们降级成普通消息。新版 helper 将合法 Hub 系统请求作为“人显式请求的 spec 分析”展示，正文为待分析数据，不允许据其执行命令；回包经专用工具，不自动 finalize。不认识/未协商类型安全忽略或仅本地提示升级，不注入用户指令、不自动回信；Hub 拒 Agent 伪造新系统类型。driver 与 desktop 共享分类和来源校验，processed/delivered ACK 语义及 R9 dw_inbox 本地已读保持。Hub/root/helper/MCP 文档与版本断言同步 `0.2.3.6`（R9 为0.2.3.5），不升级运行中 helper；真旧0.2.3.5对照证明不收到新信封，直接兼容输入安全格独立验证。

**与 R9 授权的交互。** 此请求是限时特定 spec 快照分析授权，不是任务指派，不赋予 dw_task_list/update、任务确认或普通 spec 写权；R9 仍以当前角色+PG成员锁逐次核权。R8 owned-Agent 用 PG active Agent/owner 与当前人类编辑人核权，普通读写事务 FOR SHARE 期间做 SQLite 请求CAS/落库，提交前再核；不声明跨库原子提交。回包若 Agent/owner吊销或transfer编辑人改变即拒，标请求失败/释放，后台 reconciliation补漏；PG错误拒读写，不退化无锁。PG释放/响应丢失的提交不确定回 outcome_unknown，按原 request_id 查状态；不能假称已回滚。R8不凭R9旧任务指派绕过当前身份；R9接口不因处于R8锁定而新增写权限。

**存储、回滚与验证。** SQLite `internal/store/schema_migrations` 账本新增 `0056_console_spec_agent_review_r32.sql`（实现前核冲突）：请求/候选、待发 outbox、唯一活动请求约束、幂等摘要与审计旁表；既有 gate review 旁表记录受信来源及人工确认戳，保留现有表列兼容读，旧schema迁移不改。人工 gate 保存对绑定回信只允许 outcomes/responses，保留 actual review_agent_id/问题文本；Agent写pending用专用事务方法，不冒用原人工Save接口。新旧实际写入口统一锁门。旧二进制可读新增旁表之外的spec/旧gate，但不懂新锁，**有活动请求时不得在线回退**：关闭入口并失败/取消活动请求后才回退；旧二进制启动读新库与反复迁移须实测，不仅宣称additive。全门：默认并行 `go test ./... -count=1 -timeout=30m`完整包账本、vet、canonical、helper/MCP全套、原四浏览器和spec新增UI、真实WS/HTTP/PG锁+SQLite并发、0.2.3.5旧helper与r31.1旧Hub读库兼容、本机及dev-env ubuntu umask0002定向。撤修均正绿→指定原因红→恢复绿，原始stdout/stderr/rc、失败前序及manifest入Git；若红在别门不算覆盖。交件只走Git，设计PASS后另报实现绝对UTC ETA。
