# D2 轻量档 · 卡住一次登记，有新输入再醒（一页，待审）

**试点默认路径；复杂机制作附加。** 本页按组长轻量意见追加，原 [D2 完整稿](S-PILOT-BLOCKER-WAKE.md)保留。基 r32.1 36afa621，仅设计；当前没有启用自动唤醒，也不更改真实任务。

**PM 只做三步**

1. **看一张阻塞卡。** 从任务直接点“卡住了”，只说明“卡在哪、等谁、等什么”；系统带任务/spec/执行人及已有环境/授权，不重填整套 spec。所等人未定就显示待分派，不能默认全归 PM。
2. **答复或转给能处理的人。** PM 补业务决定；技术事实、资源/授权不足转相应责任人。答复和材料都挂原卡，不要求把聊天记录再手工抄一遍任务板。
3. **看恢复结果。** 有新答复或确证条件变化时，系统自动通知并唤醒当前执行者的一次“重核”轮次；卡上显示已到件、重核中、仍缺项或已恢复。PM 不逐条催执行者、不处理内部状态字段。

**执行者最短流程。** 登记时同时选/确认恢复前需核的条件（系统从任务带出，常见为材料、依赖、当前身份/指派、环境及有效授权）。答复到件不等于条件满足；当前执行者重核通过、其他阻塞均解才恢复任务。无新输入就保持等待，不反复发“仍阻塞”；同一答复重发、断线重连、程序重启不产生新一轮业务执行。未找到所等人只待分派，不制造无人负责的假完成。

**不把四状态装成六状态。** R9 实际执行仍 planned/in_progress/blocked/done；“请求/认领”对应指派和 start，“完成申报/复核”用交付与子例确认记录，“验证/签收”另留实证与人类记录。R9 done 已含当前复核用例门，仍不等于正式平台验证或业务签收。旧入口也不能绕过未解决阻塞直接恢复/完成。

**单人也能走。** 一个人可登记、补材料、重核自己的任务；需要独立复核时用配置的审查 Agent，不虚构第二个人。若同一人也是所等人，资料就绪仍通过同一卡追加新输入和重核，不靠自发催办消息维持循环。旧 helper 不支持唤醒时明确“已通知/待升级”，不显示“已自动恢复”。

**完整档何时附加。** 轻量仍由系统负责关联、去重、离线保留和恢复前检查，PM 不填事件版本/lease/队列字段。多团队需要细分责任、并发/多条件编排时，由 owner/受委托组长选原完整档；涉及真实生产动作或安全面自动升完整档，补明确环境、授权、审计与重核证据。条件解除后降档需 owner 确认新版本，不能清历史或降低实际风险。

**不能降低：** 不伪造材料或责任接受，unknown 不算解除；唤醒不是新动作授权。尤其 STOCK 未知提交只核原任务，不能自动重派写、换 key、清 pending 或按同值签收。轻量验收看登记→答复→一次重核链、无新输入不重复、越权/旧入口拒绝、离线后不丢；内部可靠性不要求 PM 操作完整档配置。本页不改码、不启用、不上线。
