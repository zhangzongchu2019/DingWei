# D1 轻量档 · 从 PRD 到可确认 spec（一页，待审）

**试点默认轻量，完整档按风险附加。** 本页按组长轻量意见追加；原 [D1 完整稿](S-PILOT-SPEC-TEMPLATE.md)与 STOCK 附件保留不改。基 r32.1 36afa621；均为设计，不表示已实现、已建平台对象或已批准业务动作。

**PM 只做三步**

1. **贴 PRD 链接、说清目标和首个范围。** 有权连接器取到才生成草稿；无权限可提交有来源的导出文本，不借他人凭据。系统保留原文版本/来源，生成父 spec＋所选范围子 spec，不自动生成 all14。
2. **补齐并确认六项。** 每条需求/子例：**验收标准、测试方法、交付物、环境、执行人、签收人**。可继承共用值、用默认建议减少填表，但展开后仍须明确；执行/签收人须接受责任。unknown/未认领不算完成，缺什么显示什么并进待完善池。
3. **确认本版 spec。** 系统显示范围、六项和预审问题，由人确认；确认不等于授权真实操作、通过测试或业务签收。认领后不静默改正文；变更留新修订和影响提示，确认后再继续。

**一个人也能走完整程。** 多人模式复核人必填；单人模式不再强制找第二个人，可由已配置的审查 Agent 复核。系统记录其身份/接受结果，未复核仍显示未复核，同一执行 Agent 不能冒充独立审查；人类可兼任执行与业务签收角色，不伪造多人独立性。Agent 提建议，人决定业务确认/签收，不能由机器代签。

**默认值，不多设填表门。** 七属性、rule_ids/规则表版本、预授权清单等在轻量档以默认说明＋可选补充呈现，不作轻量准入阻断；不把未评估伪写成“安全面=否/已授权”。轻量底线是六项与真实责任、来源可追溯、结果如实记录；不宣称因此已满足原完整稿全部纲领门。模板和审核记录尽量自动带入，PM 不填内部字段。

**STOCK 样板。** 默认显示原 13 case ID 和各自六项；仍待 owner 选择是否首试 STOCK。保留原预算（仅 B06-applied-lost 上限 1，其余 0）与 NOT_RUN；预算不是授权，工程合成不替正式证据。三责任/环境/方法中的未定项继续显示缺口，不把“贴入模板”当签收或扩大为完整 STOCK/49 例。

**何时加完整档、谁决定。** 项目 owner/获委托组长确认档位；多团队可主动选完整档。涉及真实生产动作或安全面时自动升完整档，补齐原稿人审、属性/分级、具体预授权及相应门方，不能手动跳回轻量绕过；风险解除后经 owner 对新修订确认才降档。升降档均留原因/修订/责任人，既有失败和门记录保留。

**任何档都不降的底线：** 不伪造证据；unknown 不算完成；未授权不做真实动作；不把收到、done 或 Agent 预审当人类业务签收。验收这条默认路径时核六项缺项、单人审查、升档触发及 PM 三步即可，不要求轻量先跑完完整档机制。本页不执行实现、升级或发布。
