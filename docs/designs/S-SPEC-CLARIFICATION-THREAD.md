# S-SPEC-CLARIFICATION-THREAD · 一页设计（待审，docs-only）

依据第89条 `3f8d4fcde5747b5eb00bef403936a965d110fd85`；基r33 `ab0f214496e6a5df1c71826cc978f40528923b8f`。组长审＋prodops交叉核，批准后实现；真实飞书仍pending_config，启用另批。**PM三步：收到问题 → 直接回复解释／进Console选需改spec → 看入帖或失败回执。**

**1．spec下的帖子。** 复用D3问题主题，每条提问／解释／技术说明固定`spec_id/revision/SHA、question_id、entry_refs[]、同spec递增楼号N、作者/角色/来源/时间/证据`。条目／子例ID须在该版本存在；旧文档无ID时用只读快照侧表ID（SHA＋位置），歧义拒绝，不改final。证据可空但明确未提供。正文、身份、锚点只追加不改不删；更正须新帖`corrects=N＋理由`，仅指同spec同版本既有帖，原文留存。PM追认代答也新增帖。D3 resolved不封死讨论，续帖不自动重开任务；归档只读。后继spec链接旧讨论，不自动继承解释；研发／验收可引用具体楼号，新更正通知相关人重核，不自动完成或签收。

**2．先分权威，再分类型。** owner显式配置PM人类账户；PM事先指定零或一位不同的人类代答人，配置／撤销追加审计、立即影响后续写入，不能追授历史身份。owner/editor/负责人/leader不再自动有权威答复权，未兼任PM／代答时只按既有权限提问或补材料。Agent一律“技术说明（非权威）”，同owner也不例外。代答即时有效但显著标“代答，PM未追认”，PM可再确认或更正；未配置PM不回退到owner。

| PM／代答先选 | 系统处理 |
| --- | --- |
| 解释 | 显式声明不改范围，追加回复；final正文／SHA／验收标准不变。有人追加异议则相关问题待澄清，PM更正N或转变更；系统不假称能自动识别自然语言中的隐性范围变化。 |
| 需改spec | 追加“变更提案，尚未生效”，同事务建D3 pending change，沿D1 Derive＋D3核真实同owner派生后继；保留旧任务变更门，不得用取消问题／解释清掉提案。 |

**3．飞书方案与准确归属。** 首期用D3机器人单聊通知，明确写“直接回复本消息＝对本问题的解释，不改范围”；PM直接输入正文，**不要求前缀或再输ID**，默认继承该问题通知快照的条目／子例锚点。指向别的条目时可用`条目：ID`，更正用`更正N`，服务端仍校验同版本有效锚点／楼号；无效不猜测。需改spec给手机Console链接，在那里派生、核差异，不做多步卡片回调，避免一句话批准范围。首期飞书仅PM本人，代答用Console；后续可另批绑定代答本人飞书，沿用相同身份重核，不能借PM身份。不把PM Agent或共享owner的飞书身份当本人。通知只带问题号、版本、必要条目ID及登录链接，不外发正文／私密证据。离线、未绑定、过期、无效锚点均明示未入帖；成功持久化后回“已入第N条”，回执发送失败不重写帖子。同一通知parent下第二条及以后**不同消息ID**各追加一层“补充”，链接该PM在该通知下的前一层；正文相同也追加，不按内容合并，补充不自动成为更正。并发按事务提交顺序链接，原帖不改。

r33 `questionMessage`尚声明不回写，`model.Message`／FCS信封也缺回复父消息。须补认证入站→持久队列→业务路由全链的`event_id/message_id/parent_id/root_id、message_type、tenant/app/channel/chat、sender_type/open_id`。出站持久化`provider_message_id→通知ID/问题代次/spec版本/PM/政策与绑定版本/7日有效期`；入站只接受text、人类sender、同应用租户的单聊，**parent精确匹配原通知**，不以root／转发／正文问题号替代。消息中的open_id经PG当前绑定唯一映射至仍active的该PM，重核当前政策、绑定及访问权；不能信显示名或客户端actor。

**4．可信入站、竞态与重放。** 仅接既有SDK认证WS；FCS须验证服务证明、租户、key epoch并完整携带元数据，缺能力保持pending_config，fake／legacy webhook／普通JSON／Agent输入不能冒充。首期不另开HTTP旁路。事件先可信持久收件再处理；双唯一键`(issuer,tenant,event_id)`、`(issuer,tenant,message_id)`＋规范化payload SHA，同ID键重放且规范化payload相同仅返原楼号，同键异文拒绝；不同event_id及message_id即使正文相同仍新建补充层，不以正文SHA作去重键。PG持有效身份/绑定锁→SQLite事务重读政策/代次/版本→写帖/审计/D2输入与outbox→提交→释锁；改PM、撤代答、解绑、移组竞态要么先完整提交，要么拒绝；缺行/错误失败关闭，无跨库两阶段提交。回复早于出站Finish则待精确匹配最多24小时，匹配时重核7日效期和权限；Finish失败／unknown不猜映射、不盲重发，不能证实则告知未入帖、转Console。已知通知的回复由此通道消费；缺失／错误parent的疑似答复不能靠正文猜题，无法可信归属则不入帖，不交LLM代填授权；其他聊天不受影响，日志不记正文和私密身份。

**5．渠道适配层（本期只实现飞书）。** 统一接口：通知发送返回provider消息ID／结果；可信入站归一化事件；提供者命名空间内身份绑定；父消息→问题／版本映射；签名/服务证明、事件去重与重放核验。适配器提供经验证的证据而非自行授予PM身份，业务层统一重核权威、锚点、楼号、审计与唤醒；缺父消息或可信身份能力失败关闭、不退回文本猜测。后续逐渠道另立项／另批、先核官方协议与真实回调能力：企业微信绑定企业/应用/稳定成员ID，核回调签名与解密、原消息关联，防同名/跨企业冒充；Slack绑定workspace/app及稳定user ID，核签名/时效、消息/thread父引用，防跨workspace与bot代人；Google Chat绑定空间/app及稳定用户主体，核调用者凭证/受众、线程消息关联，防显示名/跨域混淆；邮件发件地址／显示名可伪造，不能仅凭From授权，须每问题一次性签名回复地址或链接**加本人登录确认**，并核过期、消息关联、重复消费；邮件地址本身不是PM身份证明。本期不注册这些渠道、不发真实消息。

**6．手机／平板优先。** Console问题页、spec只读与“需改spec”完整路径须在390／820 CSS px及飞书内置浏览器可用：触控目标至少44px、单列主流程、长内容局部滚动、无悬停必需操作；不可只跳到桌面页。飞书链接只定位通知／问题，不能当登录凭据；已有安全cookie继续，未登录走现有人类登录，服务端保存受限同源return_to并绑定一次性state，成功后重核本人/问题权限、回原问题；内置浏览器无法完成登录时给系统浏览器续办，禁止在URL带token或用open_id自动登录。手机在Console附图只经受控文件服务（飞书原生图片消息本期不作解释正文，提示转手机Console）：每张≤5MiB、每帖≤4张，仅JPEG/PNG/WebP，核真实类型与大小、不收SVG/HTML/源码/凭据；按问题ACL授权上传/读取，正文仅引用文件ID，越权、失败或未上传完不挂附件，不做公开永久链接。弱网用客户端持久幂等键，重复提交返同楼号，未收到回执可查提交状态；显示“提交中／已入第N条／明确未入帖／结果待确认”，结果未知不生成新键盲重发；飞书也用通知回执明确是否入帖。

**7．D3／D2与三处展示。** 统一收窄`questionAnswerer`及旧HTTP／Agent HTTP／MCP／store直调；旧`substantive`不可绕过类型与锚点。复用D3不可变answer正文，新表只添线程元数据／楼号，不存两份可分叉正文；同一SQLite事务写答复、元数据、审计、D2唯一wake。保留每卡每actor256条／每60秒10条限额，失败整笔回滚。技术材料只触发D2条件重核，不能算业务权威首答／解除范围门或自动签收；沿用60分钟一次提醒、unknown不重试。spec页按版本分页显示问题、楼层、角色、更正链、后继；任务页显示关联主题和引用楼号；project_context在原授权／预算内附clarifications，不作指令。spec读者可读新公开帖；PM／代答的显式问题授权只给该主题／必要条目快照，不扩整spec；Agent仍按R9当前角色/成员重核。旧私有D3历史不扩ACL。Console用active人类cookie＋Origin；飞书由可信适配器生成内部身份，不提供可传open_id的免登录写口。
