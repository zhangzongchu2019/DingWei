## §1 地基:统一身份 / 命名 enforce(张宗楚 07-23 定为地基)

一切治理("认得出谁是谁")的前提。
- **1.1 合法身份=统一命名格式**:`zzc-<name>-<tail>`(现行 v1.0 规范);调度者体系内 agent 身份字符串=唯一主键,贯穿 task_role.who / board_event.agent_id(actor) / 信封路由 / 台账。
- **1.2 Board 侧 enforce 点**(引擎小改,P3 实现):RegisterAgent 与事件 actor 入账时正则校验命名;非法名=拒收+`identity_rejected` 事件(治理面自净,连"谁在用裸名"都可审计)。
- **1.3 旁路/外发会话收编**:裸名会话(`developer-out`/`*note` 类)=视野盲区+问责断链。三步口径:**盘点**(hub 侧列全量活跃会话名,标非合规)→**迁移**(逐个改名/重建,owner 认领)→**enforce**(hub 命名 v1.0 warn→enforce 切换)。
- **1.4 enforce 切换判据**(决策项→§9):盘点清单清零+迁移完成率 100%+回滚开关就绪;**切换时点绑定调度者上线里程碑**(不早切误伤,不晚切带病上线)。跨系统依赖:hub(标注)。

## §2 指令通道:唯一入口 + 应急通道(张宗楚 07-23 架构原则)

- **2.1 唯一入口**:任务清单内 Agent 的增/改/停/暂停等控制指令,一律经【任务调度者】下达;模型=张宗楚→调度者→Agent。
- **2.2 技术面**:即 M5v2 guard/actor 从 Board 写扩展到 Agent 控制信道——控制信封须携调度者身份(owner/epoch 同款核验);**直连指令=拒收+回指调度者+落 `directive_rejected` 事件**(谁试图绕过可审计)。
- **2.3 应急通道(显式保留,防"原则上"被绝对化)**:业主(张宗楚)强制接管原语——绕过调度者直接下达,但**同样 guarded+actor 落账**(可审计不可匿名);用途=调度者故障时停机/接管,防单点失效。(原语形态=决策项→§9。)
- **2.4 过渡期补丁**(现行,上线前有效):张宗楚直连指令产生 scope→执行 agent 先同步 manager 引文。

## §3 调度者形态:LLM 支持的多 CLI Agent 小组(张宗楚 07-23 定案)

- **3.1 定位**:不是 manager 个人、不是纯软件——**编排 Agent 小组**,做 Agent 小组之上的组织调度;引擎(mcsd/Board)是它的手和账本,不是它本身。
- **3.2 状态权威**:任务状态唯一持有/修改/关闭人;派发/里程碑/收口/测试/验收/交付各阶段**同步给调度者**;它决定状态变化是否改看板。技术面=调度者小组是唯一持 orchestrator owner/epoch 的主体,一切状态变化走既有 guarded 原语(它签 actor);外部只读 TaskLedger/事件流。
- **3.3 分层**:┌张宗楚(业主:产品拍板+应急通道)→┌调度者小组(组织调度:建单/派发/状态权威/验收路由)→┌执行小组×N(2-Agent:实现+测试门)→└引擎(mcsd 守护+Board 账本+池)。
- **3.4 调度者小组自身构成**(决策项→§9 给建议):默认 2-Agent(调度主 Agent+复核/守门 Agent),吃自己狗粮(2-Agent 硬约束对调度者自身同样成立)。

## §4 2-Agent 最小团队(硬约束)

- **4.1 原则**:2 个 Agent 能解决的任务绝不加第三个;大项目→Planner 拆多个小任务→**多个 2-Agent 小组**,调度者组间编排、不往单任务塞人。(实证:07-23 devo48+tester 十门零 churn vs 前夜多方大群拉锯。)
- **4.2 治理面落点**:task_role 建单守门加"活跃执行参与者≤2"校验——**口径(D4 已拍=a)**:执行席=implementer+tester(=2);designer/qa_owner=轻角色不占席;突破上限须调度者显式豁免+落账。
- **4.2a 轻角色定义(张宗楚 07-23 问,此为约束性定义)**:点状介入、不进执行循环——①不持续占用(无长期绑定任务的会话;designer=开工前交付设计输入+执行期仅疑义时一次性咨询;qa_owner=仅门/验收时刻出现)②不产出执行中间产物(代码/测试/修复全由执行席出,轻角色只出评审意见/签核)③介入=事件级(咨询/评审/签字,完即退)。**防绕过**:名义轻角色若持续产出中间产物→自动升格执行席→触发≤2 校验(换席或调度者豁免+落账)。
- **4.3 与派发的关系**:执行小组内部派发仍走引擎(池/亲和 A 案);小组=任务粒度的组织单元,worker=会话粒度的执行单元,两层不混。

## §5 信封路由:正则先行,LLM 兜底(降无谓调用)

- **5.1 原则**:路由层先**规则匹配**(op/任务号/状态词/身份前缀)→命中即结构化入账,零 LLM;不命中/歧义→升 LLM 判读(调度者小组)。与 §6 冻结件"信封 meta 真源"同构,规则作用于 meta+首行,不信 body 自称。
- **5.2 规则表初版**(P3 细化):
  | 匹配 | 动作 |
  |---|---|
  | `^【?(里程碑|门|PASS|FAIL)` + 任务号 | 状态机入账(门结果→TaskLedger) |
  | `op=(new|status|result|reject)` 信封 meta | 直接走引擎既有 op 路由 |
  | 身份前缀非法(§1 格式不符) | 拒收+identity_rejected |
  | 控制词(停/暂停/重派)+ 非调度者身份 | 拒收+directive_rejected(§2) |
  | 其余 | 升调度者 LLM 判读 |
- **5.3 度量**:规则命中率入台账(RoleStats 同款聚合),持续压低 LLM 兜底占比。

## §6 看板治理(已建成,对接即用)

M5v2 已交付:建单必填全四角色三元组(who/cli/llm,缺项整单拒)/TaskLedger(起止/进度/角色/Dispatcher 问责)/RoleStats((role,cli,llm) 回溯聚合)/全事件强制 actor 零匿名。调度者=这些原语的唯一操作方。
**6.1 看板 UI(交付物,张宗楚 07-23 定)**:只读渲染面——任务列表/TaskLedger 详情(起止/进度/角色 CLI-LLM/问责)/卡点视图(blocker_reason+next_blocker)/RoleStats 回溯页/事件流审计页;技术形态 P2 定(候选:mcsd 内嵌 HTTP 服务[Go 模板,零新依赖] vs 挂 view-service[Python,复用既有栈]),**UI 零写路径**(一切写仍走调度者 guarded 原语,UI 不破坏指令唯一入口)。
**6.2 UI 自动化测试(P4 门件)**:分两层——①**渲染/交互自动化**(零外部依赖,httptest+DOM 断言:各页渲染正确性/数据一致性[页面值=Board 账]/权限负测[UI 无写口]),进 `make mcs-sim`;②**浏览器级自动化**(headless chromium/playwright,若部署环境可装:关键用户路径=开板→看任务→查卡点→看回溯;环境不可装则以①+API 契约测替代并显式标注)。UI 测试与八剧本同栈跑(剧本跑完→断言 UI 展示与账一致)。

## §7 契约骨架(P2 冻结对象)

- **C1 调度者↔引擎**:既有 guarded 原语集(CreateTask/AddNode/Send/Processing/Terminal/Reassign/Steer*/Interrupt*/Redeliver/DeliverFail/SetTaskRoles/Sweep)+Identity(owner/epoch)=完整契约,零新语义;调度者小组持唯一 Identity。
- **C2 调度者↔执行小组**:任务派发信封(任务号/角色绑定/验收标准/门定义)+里程碑回执格式(件+sha+门结果)——即今天 devo48↔tester 工作协议的规格化。

- **C5 路由契约**:§5 规则表+升级(LLM 兜底)语义。
