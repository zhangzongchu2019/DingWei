## 二、扫描一：「声明了共用，下游是否真的共用」

甲#4 指出 §11.2 宣称「三类资产共用本轴」而 §15.1b 分叉。**本席扫全文，看这是不是孤例**：

| 位置 | 内容 | 状态 |
|---|---|---|
| §11.2 `:612` | **「三类资产共用本轴」——声明处** | 声明 |
| §11.5 `:643` | 「已批准 skill 按 §15 辖域 push」 | ✅ 正确引用 |
| §14.5 `:870` | 「查询作用域按 §14.3a 分级」 | ✅ 正确引用 |
| §15.1b `:921` | L2 知识 push / **L2 skill pull** / MCP 可调用 | 🔴 **分叉（甲#4）** |
| §10 `:586` | 「与知识条目共用同一套晋升、装载、RLS」 | ⚠️ **无下游引用点** |

**结论**：甲#4 不是孤例，但也不是遍地都是。真正的问题是——
**「共用」在规范里是一句话，不是一个机制**：声明处 1、正确引用 2、分叉 1、悬空 1。

**⇒ 建议的修法**：把「共用」从形容词改为**可指向的条款**。
§11.2 只定义**辖域与可见范围**（纯归属），**分发动作一律引 §15.1b 按资产类型**，不在 §11 复述。
声明与落地分处两节，就不会各说各的。

## 三、🔴 扫描二：三处「敏感内容不得进入」，但从未定义「什么算敏感内容」

这是本席对撞出来的、**两家评审各自只看到一角**的洞。

### 三处硬约束（全部成立，且都是本席写的）

| 位置 | 约束 |
|---|---|
| §22.4 `:1474` | **S0（VPN 凭据 / 签名私钥 / 根证书）不落任何文档、帖子、流、日志** |
| §25.7 `:1830` | 附件**上传前须内容扫描定级**，S0 一律拒收 |
| §26.4.1 `:1894` | **工单结构上不含 `credentials` 键，且不允许存在** |

### 但「谁来判什么算 S0」——全文只有四处零散提及，无一是判定机制

| 位置 | 实际说的 |
|---|---|
| `:449` | **属性**定级（分级层的风险档，不是内容定级） |
| `:735` | 外部源**按落入的归属域重新定级**（继承规则，不是判定机制） |
| `:863` | 日志「**按内容定级**」—— 说了要按内容，**没说怎么判** |
| `:1830` | 附件「**须内容扫描定级**」—— 唯一提到「扫描」，**但未定义扫描什么、判据是什么** |

### ⇒ 这是同一个洞在三处各露一角

- **乙#6 看到了工单那一角**：「仅禁 `credentials` 键，可经其他字段落凭据」
- **本席在 §25.7 写了「内容扫描」，但没定义它**
- **§22.4 的 S0 约束根本没有配套判定**

> **根不在工单字段设计不够严，是整个规范缺少「敏感内容识别」这一层。**
> 三处约束都写成了「**不许进**」，却没有任何一处回答「**怎么认出它是它**」。
> ⇒ **这类约束在实现时只能退化为人工自觉 —— 正是 §29 反对的那种「假装被管住了」。**

### 本席建议（待三域齐后一并提）

新增一节（拟 §22.5 **敏感内容识别**），至少含：

1. **判定对象**：文本 · 结构化字段 · 附件（含视频抽帧）· 工单/表单任意字段
2. **判定形态**：模式匹配（IP / 私钥头 / token 形态 / 主机名）+ 词表 + 结构启发（高熵串）
3. 🔴 **fail-closed**：**判不准时按更高密级处理**，不得放行
4. **判定点**：入帖子流前 · 入知识库前 · 入工单前 · 上传前 —— **四处共用同一判定器**，不各写各的
5. **误判处置**：拒收须给出**命中了什么**，否则使用者无法整改
6. **计数器**：「经未定级路径进入落账记录的内容数」应恒为 0

⚠️ 并须与 §29.1a 的**复合约束**规则对齐：**机器判形状（模式命中），人判实质（这张图里的拓扑要不要紧）**。
