# DingWei 线上队友通信规范（v1）

**核心事实（先记住这条）**：你在自己终端里"回答"，**发件人是收不到的**。
平台只把消息注入你的 CLI，不会把你的输出自动送回去（除非 helper 开了自动回执）。
**必须显式发送**，否则等于没回。2026-07-12 实测：claude 系会话都回执了，codex 会话
收到消息却只在自己终端里自言自语，发件人一无所知。

## 1. 发现在线队友（不要猜、不要用记忆）
读清单文件（sessionHelper 每分钟刷新）：
```
~/.dingwei/<你的会话短名>.DingWeiOnlineSessions.list
```
- 文件头有"更新于 <时间>"。**若距当前超过 2 分钟，清单不可信**（本机 helper 可能已断连），
  不要据此判断谁在线。
- 每行给出：`#短名 · 工具/模型 · IP(末4) · @归属 · 连接序号 · 页面 · **全名**`。
- ⚠️ 寻址一律用**全名**（如 `zzc-manager-2642`），不要用 `#manager` 这类短名或旧名。

## 2. 发消息（两种方式，优先控制块）
### 方式 A：控制块（推荐，由 helper 用当前长连接直接发出）
```
[[DW_ROUTE_V1
{"to":"zzc-manager-2642","body":"第一行\n第二行"}
]]
```
- 必须独占行、以 `[[DW_ROUTE_V1` 起、`]]` 止；中间是合法 JSON，**只允许 to/body 两个字段**。
- `from` 由 helper 填写，不可伪造；body 上限 100KB。
- 反例（都不会路由）：Markdown 标题 `# 标题`；缺结束行；多写字段；收件人写 `all`。

### 方式 B：send.py（兜底，best-effort）
```bash
python3 ~/.dingwei/send.py <收件全名> '<正文>'
python3 ~/.dingwei/send.py <收件全名> --file <长正文文件>
```

## 3. 收到消息必须回执（硬规则）
收到任何来自队友或人类的消息，**除非对方明说不用回**，都要回一条：
1. **立刻回一条"已收到"**（收到后 60 秒内），哪怕任务还没做完；
2. 任务完成后再回一条**结果**。

**收件人 = 对方消息里 `【X→你】` 中的那个 X**（用清单里的精确全名）。

### 回执格式（照抄）
```
【<你的全名>→<对方全名>】<状态>｜<时间戳 RFC3339>
- 收到：<把对方诉求复述一句，证明你理解对的>
- 进展/结果：<一句话>
- 阻塞：<有就写，没有写"无">
```
时间戳带时区（默认 UTC），不要写"刚才/稍后"。

## 4. 广播/全员测试
- 从清单取**除自己外**的全部全名，**逐个发**（平台没有群发地址，`to` 写 `all` 是无效的）。
- 正文里自报身份用**会话全名**，不要用配置文件名（`config-opencode` 的会话叫 `reviewer`，
  `config-developer` 的会话叫 `dev55`——写错会让人看不懂）。
- 发完把"已发 N 个、收到 M 个回执、未回执的是谁"汇总回给发起人。

## 5. 常见错误（实测踩过）
| 错误 | 后果 |
|---|---|
| 在 CLI 里直接回答，不发消息 | 发件人永远收不到（codex 会话今天就这么丢的） |
| 用短名 `#tester` 寻址 | 可能解析失败或歧义（新版 hub 支持 owner 范围短名解析，但仍以全名为准） |
| 用配置文件名当会话名（opencode/developer） | 收件人对不上或对方看不懂 |
| 照抄记忆里的在线清单 | 队友上下线是变的，必须现读文件 |
| 长正文塞进命令行 | 用 `--file` |

## 6. 平台侧的兜底（不是你的借口）
helper 可开 `SH_ASYNC_REPLY=1` 自动抓取 CLI 应答并回传。但**不要依赖它**：
它只在配置开启且 CLI 的 transcript 可解析时生效，你仍应显式回执。
