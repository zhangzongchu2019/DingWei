# DingWei 版本规范（v1，2026-07-13 张宗楚拍板）

## 1. 版本号语义

统一版本号形如 **`A.B.C.D`**，**hub 与 sessionHelper 同源同值**。

**当前基线：`0.1.2.5`**（在此之前的所有版本号作废，不再有意义）。

| 位 | 名称 | 什么时候改 | 客户端是否必须升级 |
|---|---|---|---|
| **A** | **架构** | 架构升级 | **✅ 必须** |
| **B** | **通信协议** | 通信协议升级 | **✅ 必须** |
| **C** | 功能 | 功能调整 | ❌ 兼容 |
| **D** | 修复 | bug 修正 | ❌ 兼容 |

## 2. 兼容判据（hub ↔ helper）

```
hub.A != helper.A  →  拒绝连接
hub.B != helper.B  →  拒绝连接
其余                →  放行
```

- **`C` / `D` 不同 → 放行**，但在线清单显示完整版本，漂移仍然可见。
- **version 缺失或格式非法 → 按不兼容处理（fail closed）。** 旧 helper 根本不上报 version，正好落进这一类。
- **拒绝时必须返回明确原因**：当前版本、要求版本、下载地址。
  ⚠️ **绝不允许静默拒绝** —— 「连不上且不知道为什么」是本项目已经踩过的坑（T10c：send.py 默认连到非 hub 主机，静默失败无人知晓）。

## 3. `B` 位不可轻动

**每一次 `B` 变更 = 一次全网强制升级。**（helper 分布在多台机器、多个租户，其中包含非本团队的会话。）

改 `B` 之前必须确认：
1. 分发包已就绪（公开包 + 各人的含密钥个人包）；
2. 所有 owner 已被通知（含**非本团队租户**，如 `systemtaskintl`）；
3. 有回滚路径。

## 4. 唯一版本源（防漂移）

**仓库根 `VERSION` 文件是唯一真相。**

- hub：`internal/version/version.go` 的常量
- helper：`tools/sessionhelper/sessionhelper/__init__.py` 的 `__version__`
- **两者各配一个测试，断言等于 `VERSION` 文件内容** → 任一处漂移，测试立刻红。

**动因**：2026-07-13 一天之内被版本漂移咬了三次——helper 新代码上盘却未激活、旧路径 helper 残留、**发布包里是修复前的代码**。根因就是**没有唯一版本源，两边各写各的**。

## 5. 强制开关（分阶段启用）

`WP_VERSION_ENFORCE = warn | enforce`，**默认 `warn`**。

- `warn`：版本不兼容照常放行，但记日志、在线清单标记。
- `enforce`：不兼容直接拒绝握手。

**⚠️ 不得在全网升级完成前切 `enforce`** —— 否则旧 helper 连不上，连「你该升级了」这句话都收不到（鸡生蛋）。

**切 `enforce` 的判据：在线清单全部显示目标版本，零 `v?`。**（这正是 2026-07-13 上线的「客户端版本上报」的用途。）

## 6. 上线顺序（不可乱）

| 阶段 | 动作 | 完成判据 |
|---|---|---|
| 1 | 统一版本号 `0.1.2.5`（`VERSION` + hub 常量 + helper `__version__` + 两个一致性测试）；hub 握手校验；**`WP_VERSION_ENFORCE` 默认 `warn`** | 部署后所有会话仍在线 |
| 2 | 重打 `0.1.2.5` 分发包，**删除旧包**（免得有人装了个会被拒的版本） | 公网可下、sha256 一致 |
| 3 | 全网升级（本机 / ts3 / shenceclaude / 符磊 / 谭平 / Mac / **secops71 需先问其 owner**） | —— |
| 4 | 核对在线清单 | **全部目标版本，零 `v?`** |
| 5 | 切 `WP_VERSION_ENFORCE=enforce` | 旧 helper 被拒**且知道原因** |
| 6 | 协议类改造（如「会话间消息统一走 DeliveryInbox」）→ **`B+1` → `0.2.0.0`** | 此时不必写任何兼容代码 |
