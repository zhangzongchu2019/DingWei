## 一 修复本体(4 行有效改动,+16/-4 含注释)

    1186  let streamEverOpened = false;        ← 🔴 从 connectEventStream() 的**闭包局部**提到模块级
    3841  if (streamEverOpened) markStreamReconnect();
    3842  streamEverOpened = true;

根因(读码,已由实测逐条对上):`everOpened` 是 `connectEventStream()` 的局部,
而 0.2.1.2 的自建重连每次都 **新建** EventSource(`scheduleReconnect → setTimeout → connectEventStream`)
⇒ 它每次重连都归零 ⇒ `if (everOpened)` 那支在**已发的自动重连路径上从不执行**
⇒ `consumeReconnectClear()` 永不为真 ⇒ `resetConversation()` 永不运行 ⇒ 每次重连追加一整份 ring。
EventSource **原生**重连是"同一对象二次 open",所以这个 bug 在 0.2.1.2 之前不成立(定界件腿B/腿C 实测)。

🔴 **为什么 arm 必须在 `open`,不能提前到 `scheduleReconnect`**(实现注记,不是空话):
`REPLAY_HARD_LIMIT_MS = 1000`(`renderer-canary-sse.html:1424`,实测值),窗口从 **arm 那一刻**起算,
而 backoff 首档就是 `1000ms` ⇒ 提前 arm 会让窗口在重放到达前就过期 ⇒ 等于没修。
**变异 MR4 就是这个错修法,闸抓到了**:`mark=14` 但 `reset=0`,正文照涨到 107520 字。

### 9.1 判据与装置

⇒ 新增 `FIRST_DELAY`(**首条事件之前**的静默秒数),`view-service/renderer-sse-fixture.py` +11/-1。
默认 `0` ⇒ 对既有三个夹具用户(reconnect / smoke / profile)**零行为变化**(第九节 9.7 实测复核)。
文件里写了注释说明它与 `DELAY` 为什么是两件事 —— 这正是"注释里写了不等于写了"的反面:
**旋钮本身必须存在,注释只解释它为什么必须存在。**

**② 不靠推断,直接读页面内部状态。** `pendingReconnectClear` / `streamEverOpened` /

刷新后 1.3s 又会出窗一次 ⇒ **告警会再来**。
🔵 也就是说:**刷新治的是"这一次叠了",治不了"hub 一直慢"**。后者只有 ⑰ 能治。
上线后若业主反映"刷新完又弹",那不是 (c) 写错了,是 hub/ring 那一侧的量**该被看见**。

### 10.10 🔴 这一节没验到什么(逐条)

1. **告警分不清两种成因**:窗口过期既可能是"重放慢"(刷新是对的),也可能是
   **"ring 是空的(hub 重启过)"** —— 后者刷新会**白页**(T-086 那块地:ring 纯内存,重启前的历史确实没了)。
   产品侧**无法区分**:两者走的是同一个 `setTimeout` 到期,那一刻拿不到"ring 里有没有东西"。
   🔴 **请组长转业主裁**:文案要不要加一句"若刷新后为空,说明 hub 重启过、那批历史确实没了"。
   (我没自己加 —— 措辞是产品可见项,而且**加了也没验过**。)
2. **`document.hidden` 时不告警**(沿用既有语义:`showStreamAlert` 第一行就 return):
   标签页在后台时窗口过期 ⇒ 什么都不显示,**回到前台也不会补** ⇒ 那一次静默仍然是静默。
   🔵 没验过业主的 web-view 在实际使用中会不会长时间处于 hidden。
3. **真 hub / 真 console 的告警触发频率未知**(9.8 全是读码;本轮全在夹具上)⇒ 上线后**可能很吵**。
   🔴 若吵,那是 ⑰ 的活,**不是把告警删掉**。
4. **端到端 26 条全在独立 renderer 页 + 浅色 + 1280x900 下跑**;10.7 只量了**外观**(4 档)。
   🔵 与遮罩那格不同:告警元素**不用** `position:fixed`(它是 `main` 里 `flex:0 0 auto` 的常规流)
   ⇒ "iframe 视口"这件事对它**推论上无关**;但 🔴 **推论等价 ≠ 实测等价**(ts-No.4 ③ 的教训),
   所以列在这儿,不写成"已覆盖"。
5. **没有断言钉 handler 的行为**:10.6 那次点击是**一次性探针,未入仓**。
   ⇒ 若将来有人把 `:4225`(锚 `cf6f4736`)那句 reload 改回 `connectEventStream()`,**全仓零转红**
   (按钮标签还是【刷新】,闸只看标签)。🔵 **这是本节我认为最该补、但本版没补的一条。**
6. **`clearReplayTimeoutAlert()` 只有一个调用点**(`consumeReconnectClear()` 为真那一支)。
   若将来清空改到别处消费,撤销路径就断 ⇒ 告警会赖着不走。没有断言钉它(它钉的是当前修法,不是不变量)。
7. **边界未细化**(故意,见 9.2):告警在 850ms 出现算不算对?**没验**,判据允许它。
8. **1000ms 这个窗口值本身仍是一对没有闸的隐式契约**(⑲ 的原判):本轮只让"过期"变可见,
   没有给窗口值定规格。改窗口值(例如 (a) 放宽到 5000ms)⇒ L3/L4 的 `firstDelay` 与守卫会红,
   **但那是腿要重定边界,不是产品错。**
