## 二 🔴 "不许另写一份清单"是怎么做到的(不靠注释,靠闸)

    权威源   deploy/nginx-dingwei.conf 的 types{ image/jpeg jpg; … image/tiff tiff; }   ⇒ 8 种
    仓内落地 FILE_EXT_KIND 的 image 行(`:2645`)⇒ 9 项 = nginx 那 8 种 ＋ 已登记别名 `jpeg`
    判据链   markdown → isInlineImageUrl → kindFromExt → FILE_EXT_NEVER_INLINE(写死) → FILE_EXT_KIND
    闸       G0 五道:
             (a) nginx 解析自证:解不出 image/* 行 ⇒ **报错**(不是静默通过);8 种必须都在 /f/ 的 location 正则里
             (b) 漂移:nginx 有、表里没有 ⇒ 红(改前实测红:`avif heic bmp tiff`)
             (c) 反向:表里多出来的必须**恰好**是 `['jpeg']` ⇒ 多一个就得说出依据,否则红
             (d) deny-set 6 个 token 逐个绝对断言 ＋ 与 image 行不相交
             (e) 🔴 **"只有一份"这件事本身也有闸**:`avif`/`heic`/`tiff` 这三个独有 token 在产品源码里
                 **只许出现一次**;出现第二次 ⇒ 有人另写了一份清单 ⇒ 红

🔵 (e) 是我自己加的:组长那句"两份必漂移"要成立,得有人**数**。光靠"我在注释里写了单一事实源"没用
—— 本组的规矩是**靠记得 = 没有**。
🔵 因为 (e),我在 `FILE_EXT_KIND` 上方那段注释里**故意没有把 8 个扩展名再抄一遍**(抄了就红)。
代价是注释不如以前直白;我认为这个代价值得,若组长认为不值,(e) 可以放宽成"只数 `avif`"。

**为什么补进表里的 4 种不只影响 markdown(🔴 副作用,必须报)**:`FILE_EXT_KIND` 是**附件降级路径**
(HEAD 不可用时按扩展名分派)在用的同一张表 ⇒ 补进 `avif/heic/bmp/tiff` 之后,
**裸 URL 形式的这 4 种图在降级路径上也会内联成 `<img>`**(此前落"下载链接")。
🔵 我判这是**修掉一个既有不一致**、不是新增行为:HEAD 路径早就内联它们了(`kindFromMediaType('image/avif')==='image'`,读码),
只有降级路径不内联 —— 正是产品件 `:2641` 那段注释自己点名的病:「同一个文件两条路径两种结果」。
🔴 这条副作用**有闸**:G9 用 HEAD 405 逼出降级路径,8 种扩展名逐个断言 `data-kind=image` `dispatch=ext`。
🔴 且 `0206` 件(附件那条路的 41 条断言)实跑 **41/0** ⇒ 老路没被碰坏。

## 三 🔴 派工单之外我自作主张加的三件(逐件给依据,请裁)

### (a) 只对**本站 `/f/` 直链**就地出图;外站图片 URL 仍是链接,且**零外部请求**

**依据(读码 + 实测)**:产品件自己写着(附件那条路的前提,`:2582` 附近):
「只认本站 /f/ 直链(附录 A1 的 URL 前缀),**不对任意外站 URL 做任何请求**」。
若 markdown 这条新路对外站图也出 `<img>`,浏览器就会去请求外站 ⇒ **推翻这条既有不变量**
(外站可借此拿到访问者 IP/时机,消息里也能埋追踪像素)。
⇒ 我判:**放开它是产品可见决定,归业主**,不在本格顺手改。

**闸**:G4 —— 外站 `.png` 三种写法(`![]()`/`[]()`/裸 URL)⇒ 就地 `<img>` **0** 张、链接照旧、
**请求账目:总 4 条 · 外部 0 条**(账目逐条打印,可审)。**M-G5** 把 `isOwnFileUrl` 那一项拆掉 ⇒ 外部请求 **0→2**。

🔴 **这里量到一件我要单独报的事**:M-G5 下 **DOM 观测量一动不动**(`extImgs 0→0`),
**只有请求账目动了(0→2)**。成因:外站图请求失败 ⇒ 产品的 error 分支把就地那张 `<img>` **撤掉**了
⇒ 扫 DOM 时它已经不在。
🔵 也就是说:**"就地那张在不在"这个观测量,对"有没有向外站发请求"这件事是盲的**;
是**第二个独立观测量(网络账目)**抓住了它。这正是组长新立那条"盲量"纪律的又一例,
而且形状是新的:不是观测量选错,是**产品的失败兜底把证据抹掉了**。
⇒ 所以 G4 的判据写的是**请求账目**,不是 DOM。

**待裁**:业主要不要外站图也预览?要的话得由他解除上面那条不变量(我再补一版,含 `referrerpolicy` 与失败兜底口径)。

### (b) 一图**不显示两处**(附件卡"让位"规则,三层)

**为什么会撞**:正文里的本站 `/f/` 直链**早就**会被 `attachFileRenders` 扫出来建一张附件卡(卡里就是 `<img>`,
`0206` 件 41 条断言钉着)。派工单① 落地后,同一条 URL 会**既就地出图、又在下面出一张卡**。
🔵 这不是我推测的:改前改后都实测过(G5 的 M-G4 对照:拆掉让位规则 ⇒ 同一 URL 的卡 **0→1**,就地图恒为 1)。

**判据为什么是"当前 DOM 里那张 `<img>` 的状态",不是"这条 URL 写在 markdown 语法里"**(🔴 两条都是实测形状):
- **超长正文只渲染开头摘要**(`LONGTEXT_EXCERPT=1200`)⇒ 摘要外的图**不会**就地出现 ⇒ 卡必须照旧建,
  否则那张图**直接没了**(比现状差)。
- **图取不到**(7 天保留期到了 / 解不了码)⇒ 就地那张撤掉 ⇒ 卡照旧给
  「文件已不可取(服务端 404)——可能已过 7 天保留期被清理」与「⬇ 下载图片」的出路。
  🔵 这一条对 `0.2.1.50` **特别要紧**:spec 正文里嵌的图,7 天后就是死链(我 ts-No.75 §二-6 量过)。
  ⇒ 修完不许把"为什么图没了"这句话弄丢。G6 逐字钉住它。

**三层实现**(`:2968` 建卡前跳过 · `:2981` HEAD 探测回来时撤卡 · `:3026` `wireMarkdownImages` 的 load/error):
🔴 **拆一层不够**(M-G4 第一跑只拆了一层 ⇒ 观测量一动不动 ⇒ 那条对照红成"探针没牙";真相是**变异等价**)。
两个渲染点都接了线(`:3300` 回合重建 · `:3468` 流式),否则每个 chunk 重渲后让位就失效。

### (c) `![alt](**非图片** URL)` 的感叹号也一起去掉

派工单②只说了图片那条。但正则的 `(!?)` 是**无条件**吃掉感叹号的 ⇒ `![报告](…/x.pdf)` 也从「!报告」变成「报告」。
**依据**:业主逐字「**感叹号可以不用了**」—— 我按直读实现(那个孤零零的 `!` 在任何目标下都是噪声)。
🔵 若组长认为非图片目标该保留 `!`,改一行即可(`bang ? '!' + link : link`),但 G2 的断言要跟着改。
🔴 M-G1 那跑顺带把这件事量清楚了:掏空图片判据后感叹号**仍然是 false** ⇒
**"感叹号消失"与"判成图片"是两件独立的事**,分别由 G2 与 G1 钉(我第一跑把两者写进同一条判据,错了,已改)。

### 🔴 四处第一跑红,**没有一条是产品缺陷**

   而不是来自"nginx 反正 404"。
3. **M-G4 的变异是等价的**:让位规则有三层,我只拆了第一层 ⇒ 剩下两层照样把重复卡撤掉 ⇒ 观测量不动。

   ⇒ 三层全拆,并把"拆一层不够"记成结论(这条规则是三层冗余的)。
