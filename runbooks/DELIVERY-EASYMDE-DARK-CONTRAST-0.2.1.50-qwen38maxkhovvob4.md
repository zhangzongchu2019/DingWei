## 七 定因(D6,**实测**;读码/规范部分单独标)

    基线(暗色,未变异)  图标 color = rgb(255,255,255) · button color = rgb(255,255,255)
                          --text = #eef2f6(≠ 纯白)· color-scheme(body/html)= dark / light
    变异(强制 light)     :root{color-scheme:light !important}[data-theme="dark"]{color-scheme:light !important}
    实测                  图标 color = **rgb(0,0,0)** · color-scheme = light · 🔴 守卫:--bg 仍 #111316(否则量的不是同一个主题)

🧪 **实测结论**:图标色**随 `color-scheme` 翻转**,而 `--text`(`#eef2f6`)全程没动 ⇒ 白色**不是**来自本仓 `--text`。
📖 **这一句是规范知识,不是实测**:该初始值在 CSS 里叫 `canvastext`(UA 调色板,随 `color-scheme` 走)。
**我能实测的只是"它随 color-scheme 翻转"**;把它命名成 `canvastext` 是读规范得来的。
🔴 **出事的机制**:本仓两个主题都设了 `color-scheme`(`renderer-canary-sse.html:9` light / `:27` dark)⇒ **常态图标两种主题都对**;
而 EasyMDE 给 hover/`.active` **写死** `background:#fcfcfc`(不跟主题),图标色却仍随 `color-scheme` 走 ⇒ 暗色下**白压白**。

## 十 D8 风险显影:那条 bare `pre` 若被**提特异性**会怎样

**为什么要这一格**:D5 实测出"现在挡住它的是 CodeMirror 的**特异性**",而特异性**不是设计**,
`!important` 会**直接越过**它 ⇒ 引入 EasyMDE 之后,任何人给本仓那条 `pre` 加 `!important`(或把它挪进 `.foo pre`)都会改变结果,
而**现有闸一条都不会红**(产品里现在没有编辑器)。

    变异(只在夹具里)  pre{color:var(--code-text) !important}          --code-text = #e6edf3(🔵 **主题无关**,两种主题同一个值)
    守卫                --bg 必须不变(否则分不清是 pre 的作用还是主题塌了)· pre 色必须**真的**变成 --code-text(归因守卫)

| 层 | 基线(暗色) | 变异后 | 读法 |
|---|---|---|---|
| ① CSS/pre 层 | `pre.CodeMirror-line` 色 `rgb(0,0,0)`,对编辑区白底 **21** | `rgb(230,237,243)`,**1.182** | 🔴 近白压白 |
| ② token 层 | 最坏 token **2.159**;继承 pre 色的 span **18/26** | 最坏 token **1.182**;继承 span **18/26** | 🔴 **18/26 = 69%** 的正文 span 跟着变 |
| ③ 像素层 | 最暗 `[0,0,0]`,`contrast_max` **21** | 最暗 `[0,0,0]`,`contrast_max` **21** | 🔵 **一动不动** |

🔴 **实测后果(可见层)**:`18/26` 个 `cm-*` span 跟着 `pre` 变成 `#e6edf3` ⇒ 最坏 token 从 `2.159` 掉到 **`1.182`**。
🧪 **变异后编辑区里只剩 3 种 token 色**(逐字实测):`rgb(230,237,243)`(那 18 个)· `rgb(170,178,179)`(`cm-url`/`cm-string`)·
`rgb(127,140,141)`(`cm-link`/`cm-quote`);基线里的 `rgb(0,0,0)` **整组消失** —— 它原本就是那 18 个继承 span 的颜色。
🔵 剩下 8 个 span 自带主题色(`2.159` / `3.478`)⇒ 它们**不随这条变异变**(而且**本来就不合格**,与本发无关)。
🔴 **一处我原先写错、已更正的话**:我初稿写"那 8 个 span 仍是黑的,所以业主只看见**一部分**正文消失"
⇒ **实测不是**:那 8 个是**灰**的(`rgb(170,178,179)` / `rgb(127,140,141)`),不是黑的;`rgb(0,0,0)` 一组都没留下。
🔵 **另一个未定因的量**:像素层"最暗 `[0,0,0]`"在变异后**仍在**,而 token 色里已经没有纯黑 ⇒
它**不是**正文墨迹(最可能是 CodeMirror 光标的黑边,**但这是推断,我没实测**)
⇒ 🔴 **所以我不拿它当"正文还在"的证据**;它恰好再次说明 ③ 这一维在本格**没有分辨力**。
🔵 **"18/26"是 span 数,不是字数** —— 每个 span 承载的字符数**未量**,所以"业主会看见多少正文消失"我只说到 span 占比。

🔵 **③ 为什么一动不动,以及这件事的分量**:`contrast_max` 取的是整块截图的**最暗/最亮对**;
剩下 8 个黑色 span 把"最暗"钉在 `[0,0,0]` ⇒ **部分**文字变不可见时它**一动不动**。
🔴 **所以"像素层没红"不能被读成"正文没事"** —— 这一维只能靠 ② 按 span 数。
(与 §六 那条同型:像素层的 `contrast_max` 也看不见工具栏的白压白。)

🔵 **引入时的对策(供裁,未落地)**:把本仓那条 `pre` 收窄成 `:not(.CodeMirror-line)`,或给编辑区显式写 `color`;
🔴 并且**必须有一条闸钉住"本仓 `pre` × 编辑器行元素"这个组合** —— 否则它就是**下一个 U7**
(东西建好了、没人验、变异零转红)。

## 十一 🔴 探针第一次红(**两条,全是我的件,没有一条是产品缺陷**)

**1️⃣ D8 第一版调了一个 `MUTS` 里根本不存在的键(`precascade`)** ⇒ 注入为空,**量的是未变异的页面**。
红的是它自己那道守卫:「提特异性之后正文**仍合格** ⇒ 反常,先查装置」。
🔵 **守卫咬住了写守卫的人**(今天第四例:`0.2.1.7` 装配 / ts-No.72 / ts-No.76 / 本件)。
修法:补上变异键 **+ 加一条归因守卫**(`pre.CodeMirror-line` 的计算色必须**真的**变成 `--code-text`,否则一律判**装置问题**)。
🔴 这条守卫的意义:**"没变"既不许被读成"没风险",也不许被读成"有牙"** —— 必须先证明变异打进去了。

**2️⃣ 第一版 D8 断言选错了观测量**:它断在 `正文基础色(.CodeMirror color vs bg)` 那一行,
而 `.CodeMirror` 是个 **`div`**,**不是** `pre` ⇒ **即使变异生效它也一动不动**(实测两腿都是 `21`)。
修法:换成 §十 那**三层**(pre 层 / token 层 / 像素层),并且**明确标注像素层对这一维不敏感**。

🔵 **同型教训**:这两条都是"**读码写断言、没先量一遍这个观测量能不能看见变异**" —— 与 U7(截屏忽略选区)、㉒(拽底)完全同族。
